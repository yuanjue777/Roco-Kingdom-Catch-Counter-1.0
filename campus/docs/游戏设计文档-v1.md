# 第零部分 · 给实现者的说明

## 0.1 这份文档怎么用

每次开始实现一个系统时,先阅读:

1. 第一部分(设计支柱)——理解为什么这么设计,遇到文档没覆盖的细节时按支柱推断
2. 第七部分(技术架构)——数据契约、系统分层、命名规范,**这部分是硬约束**
3. 你要实现的那个系统的章节

## 0.2 硬性约束

以下规则任何时候都不能违反:

1. **分层依赖单向**。下层不得知道上层的存在,不得引用上层类型。分层见 7.1。
2. **系统之间不直接调用,通过事件总线通信**。唯一例外是向下查询(上层可以读下层的只读接口)。
3. **任何游戏数值在使用前必须经过数值修正管线**。不要在业务代码里写死数字。
4. **所有运行时状态必须可序列化**。存档是随时保存,不是检查点保存。
5. **不要发明文档里没有的机制**。有疑问就在实现里留 TODO 并报告,不要自行补全。

## 0.3 遇到冲突时

如果本文档某处与另一处矛盾,以**更靠后的章节**为准,并报告矛盾点。

# 第一部分 · 游戏概述

## 1.1 一句话

你是唯一一个睡过头的学生。醒来时,学校已经不是学校了。

## 1.2 核心循环

```
白天:规划 → 潜行外出 → 搜刮/推进目标 → 天黑前返回据点
夜晚:处理需求(吃/喝/做饭/治伤) → 睡觉 → 或冒险夜行
```

玩家反复做的那件事是:**在有限的时间和噪音预算内,决定今天去哪、拿什么、什么时候撤。**

## 1.3 设计支柱

这四条决定所有取舍。当某个设计选项与支柱冲突时,砍掉这个选项。

### 支柱一:声音是唯一的通货

玩家的每个动作都有噪音代价。跑得快就吵,搜得快就吵,砸门就更吵。所有难度、所有紧张感都来自"我这么做会被多远的东西听见"。

**推论:** 任何新机制加入前先问——它有噪音代价吗?没有的话,它凭什么存在?

### 支柱二:世界是有限的,并且会被永久改变

丧尸有限、物资有限、不刷新。你今天清掉的走廊明天真的是空的;你今天喝掉的水明天真的没了。

**推论:** 不做任何形式的刷新式重复内容。玩家的每一次行动都是不可逆的资源决策。

### 支柱三:玩家应该能在脑内推演

声音传播、丧尸反应、需求消耗速率——全部是确定性的、可预测的。没有隐藏的随机数决定生死。

**推论:** 死亡永远是玩家能复盘的。"我不该那时候跑"而不是"我运气不好"。

### 支柱四:三十天是一条下坡路

难度不来自敌人变强,来自资源变少、水源断绝、丧尸重新分布。玩家越到后期越被迫走出舒适区。

---

## 1.4 三幕结构

| 幕 | 天数 | 主题 | 玩家状态 |
|---|---|---|---|
| 第一幕 | 1–5 | 求生 | 只有宿舍楼。找水找吃的,建立据点。任何一只丧尸都是致命威胁 |
| 第二幕 | 6–18 | 立足 | 走出宿舍楼。解决可持续水源与食物,获得第一件武器,发现三条结局线索 |
| 第三幕 | 19–30 | 抉择 | 物资枯竭,尸群迁移。选定一个结局并全力推进 |

**第 8 天自来水停供**是第一幕到第二幕的强制推力。**第 15 天首次尸群迁移**是第二幕到第三幕的推力。

# 第二部分 · 目标与结局

## 2.1 结局总览

三个结局互斥,玩家在一局中只能达成一个。它们的资源需求和时间需求不同,构成核心战略选择。

| | 结局一 等待救援 | 结局二 净化 | 结局三 逃离 |
|---|---|---|---|
| 最早可完成 | 第 30 天 | 约第 22 天 | 约第 9 天 |
| 难度 | 中 | 高(真结局) | 低–中 |
| 核心考验 | 资源可持续 + 最终守城 | 探索完整度 + 系统性准备 | 机械修复 + 一次成功的突围 |
| 需要幸存者 | 否 | 是(≥3) | 否 |

## 2.2 结局一 · 等待救援

**触发:** 存活至第 30 天 07:00

**流程:**
- 第 1 天起,玩家可以在多处找到收音机零件。组装收音机不是必需,但**没有收音机就不会触发第 27 天事件**,玩家会莫名其妙地在第 30 天什么也没发生。所以收音机应该在第一幕就被强引导(宿舍楼内有一台坏的,零件散落在校内)。
- 第 27 天 08:00,收音机接收到军方广播:救援直升机将于第 30 天 07:00 抵达,要求幸存者**启动并维持一个定位信标**。
- 信标位于**行政楼天台**(或体育馆屋顶,二选一,由地图设计定)。启动需要:发电机 + 柴油 ×2 + 信标装置(在保安室或行政楼)。
- 信标一旦启动,**持续发出响度 90 的噪音**,不能关闭。全校剩余丧尸开始向该建筑汇聚。
- 玩家必须在该建筑内**坚守三个夜晚**(第 27、28、29 夜)。丧尸会持续冲击建筑入口。
- 第 30 天 07:00,直升机抵达,结局达成。

**设计意图:** 把"活满三十天"从数日子变成一场有明确高潮的攻防战。玩家前 26 天所有的准备(封门材料、武器、药品、食物储备)在这三夜集中兑现。

**失败处理:** 若在守城期间死亡,正常删档重开。若信标被破坏(丧尸可以破坏),需要修复,修复期间计时暂停。

## 2.3 结局二 · 净化

**触发:** 完成全部前置条件后,在广播室执行「净化计划」

**前置条件(全部必须完成):**

1. **封锁全部出入口。** 校园共 6 个可通行出入口:正门、后门、东侧门、围墙破口 ×3。每个封锁需要 建材 ×N + 现场作业 90 秒(作业期间持续产生响度 55 的噪音)。
2. **招募 ≥3 名幸存者。** 见第六部分。
3. **修复广播系统。** 需要:广播室钥匙(行政楼办公室)+ 发电机 + 柴油 ×3 + 广播设备零件 ×2 + 手艺熟练度 ≥3。
4. **改造操场。** 操场是唯一的围困点。需要在操场周边布置 4 处可关闭的闸口(建材 ×N),并打通一条从广播室到操场的引导路线(沿途所有门必须处于 Open 状态)。

**执行:**
- 玩家在广播室开启广播(响度 150,覆盖全校)。
- 全校剩余丧尸开始向广播室方向移动。玩家必须**在丧尸抵达前撤离广播室,沿引导路线跑到操场**,由幸存者在玩家通过后依次关闭闸口。
- 这是一段**约 4 分钟的追逐段落**,玩家全程被大量丧尸追赶。中途可以用投掷物微调丧尸流向。
- 全部丧尸进入操场后关闭最后一道闸口,结局达成。

**设计意图:** 这是唯一一个把整局游戏所有系统都用上的段落。它应该很难,并且值得。

**注意:** 执行前必须给玩家明确警告,并允许取消。这不是一个可以试错的操作。

## 2.4 结局三 · 逃离

**触发:** 使用一种可行的离校方式并驶出/走出校园

**两条路径:**

- **3a 车辆逃离(较好结局):** 车棚有一辆报废的电动摩托、一辆校车。修复需要 零件 ×3 + 电瓶/柴油 + 手艺熟练度 ≥2。修好后从正门驶出(正门必须未被封锁)。
- **3b 徒步逃离(最差结局):** 从任一围墙破口徒步离开。不需要任何物品,但破口周边有密集丧尸群,必须清出通路或用投掷物引开。

**设计意图:** 这是"随时可以放弃"的出口。它应该始终可用,让玩家在绝望时有选择。片尾会明确告知玩家放弃了什么(例如"你没能带走任何人"),但**不做道德说教**。

## 2.5 目标的呈现

玩家不通过任务列表得知这些。所有目标通过**环境叙事**发现:

- 收音机广播 → 结局一
- 保安室的校园平面图 + 被幸存者写在墙上的字条 → 结局二
- 车棚的车 + 门卫室的钥匙 → 结局三

UI 里有一本**笔记本**,记录玩家已发现的线索、地图标记、配方。它是被动记录,不给指引。

# 第三部分 · 时间与需求

## 3.1 时间

| 项 | 值 |
|---|---|
| 1 游戏小时 | 85 秒真实时间 |
| 白天 | 07:00 – 19:00(12 小时 = 17 分钟) |
| 夜晚 | 19:00 – 07:00(12 小时 = 17 分钟) |
| 完整昼夜 | 34 分钟 |

**夜间声音系数**从 19:00 起在 30 分钟(游戏内)内平滑降至 0.7,05:30 起平滑回到 1.0。不做整点硬切换。

**光照**同样平滑过渡。19:00 后室内没有光源则接近全黑,必须使用手电(手电有电量,且会被丧尸看见)。

> **调优提示:** 17 分钟的白天对整个校园地图来说偏紧。第一幕(只在宿舍楼)刚刚好,第二幕可能会让玩家频繁在"来不及回家"的焦虑里。实现后优先测这个数,备选值 20 或 22 分钟。这个参数必须放在配置文件里,不要写死。

## 3.2 生命条与挤占机制

**生命条总长 100 单位。** 长度固定不变。

饥饿与口渴各自会在生命条**右端**生成一段挤占区,吃掉相应长度的可用生命上限:

```
[========= 可用生命 =========][== 饥饿 ==][= 口渴 =]
```

**规则:**

- `可用生命上限 = 100 − 饥饿挤占 − 口渴挤占`
- 当前生命值不能超过可用生命上限。若挤占增长导致上限低于当前生命值,当前生命值被**压低**(这就是饿死渴死的机制)
- 可用生命上限降至 0 → 死亡
- 进食/饮水**立即**减少对应挤占区,可用生命上限立即恢复
- **但当前生命值不会因此恢复。** 挤占解除只是解锁了上限,受过的伤要单独治

| 需求 | 从 0 涨满 100 所需 | 折算 | 说明 |
|---|---|---|---|
| 口渴 | 30 游戏小时 | 约 2.5 天 | 单独不管必死 |
| 饥饿 | 96 游戏小时 | 4 天 | 涨得慢但一旦上去很难压下 |

两者相加超过 100 时,取 100(死亡)。实际上玩家通常在第 25 小时左右因为两者叠加而死。

**恢复量:**

| 物品 | 减少口渴 | 减少饥饿 | 备注 |
|---|---|---|---|
| 瓶装水 500ml | 25 | 0 | |
| 煮沸的水 | 22 | 0 | |
| 未处理的水 | 25 | 0 | 40% 概率获得「腹泻」,持续消耗额外水分 |
| 饼干/面包 | 3 | 12 | |
| 泡面(干吃) | −5 | 15 | 加重口渴 |
| 泡面(泡开) | 8 | 25 | 需要热水 |
| 烹饪食物(基础) | 5 | 35 | 见烹饪系统 |
| 烹饪食物(熟练度 5) | 8 | 50 | |

## 3.3 体力条与困乏

**体力条总长 100。** 同样固定,由困乏从右端挤占。

- `可用体力上限 = 100 − 困乏挤占`
- 困乏在清醒时以 **5 点 / 游戏小时** 增长(20 小时挤满)
- 睡眠期间以 **12 点 / 游戏小时** 下降
- 因此每天必须睡约 7–8 小时

**体力消耗与恢复:**

| 行为 | 体力 |
|---|---|
| 奔跑 | −8 / 秒 |
| 屏息 | −3 / 秒 |
| 攀爬/翻窗 | −12 / 次 |
| 近战挥击 | −6 / 次 |
| 站立不动 | +6 / 秒 |
| 蹲下不动 | +9 / 秒 |

体力归零时无法奔跑,移动速度降低 30%,视野边缘出现呼吸效果(**这个效果本身会产生响度 25 的喘息声**——体力耗尽在潜行时是致命的)。

## 3.4 睡眠

**睡眠需要一个「安全睡点」。** 判定条件:

1. 所在房间的所有 Portal 处于 `Closed` 或 `Blocked`
2. 房间内及相邻节点没有丧尸
3. 有床或睡袋

**睡眠过程:**

- 玩家选择睡眠时长(最多 10 小时)
- 睡眠期间时间加速推进,饥饿口渴**正常累积**
- 若睡眠期间有响度到达玩家所在节点且 `margin > 15`,**睡眠中断**,玩家惊醒,并且不获得当次睡眠的任何 buff
- 中断后可以重新入睡

**精力充沛 buff:**
- 条件:在 22:00 之前入睡,且连续睡眠 ≥ 6 小时未被中断
- 效果:次日 24 小时内,困乏增长速率 −25%,体力回复速率 +15%
- 这个 buff 是玩家规划一天的主要动机——它把"天黑前回家"变成了有正反馈的行为

## 3.5 夜行

夜晚不是纯惩罚。夜行的收益:

- **多出一整个 17 分钟的行动窗口**,对赶进度极为关键
- 丧尸在夜间**视觉感知半径减半**(听觉不变),纯潜行反而更容易
- 部分丧尸在夜间会**回到固定的聚集点**(教室、宿舍),导致某些区域夜间反而空旷

夜行的代价:

- 声音传播距离增加约 43%
- 必须用手电,手电光会被丧尸看见(视觉感知半径对持灯玩家 ×1.8)
- 放弃精力充沛 buff,次日困乏加速
- 若整夜未睡,次日困乏挤占已接近满值,几乎无法奔跑

**这是一个明确的借贷:今晚多干一轮活,明天付利息。**

# 第四部分 · 玩家

## 4.1 移动与姿态

| 姿态 | 速度 | 基础响度 | 说明 |
|---|---|---|---|
| 站立行走 | 2.4 m/s | 20 | |
| 奔跑 | 4.6 m/s | 45 | 消耗体力 |
| 蹲行 | 1.2 m/s | 10 | |
| 贴墙移动 | 1.0 m/s | 14 | 必须贴在墙面上,见 4.2 |
| 静止 | 0 | 0 | |

所有响度值需经修正管线查询,受**静步熟练度**和**负重**影响:

```
最终响度 = 基础响度 × (1 − 静步减免) × (1 + 0.5 × 负重比)
```

## 4.2 潜行动作

**贴墙(Lean to wall)**
- 靠近墙面按键贴附,玩家角色紧贴墙面移动
- 贴墙时可以**探头**(左/右),探头时头部伸出墙角,能看到拐角另一侧,身体仍在掩体后
- 探头时丧尸对玩家的视觉判定只针对头部,被发现概率大幅降低
- 贴墙移动响度 14,低于普通行走

**探头(Peek)**
- 站立/蹲下时也可以左右侧身探头(不需要贴墙)
- 侧身时移动速度降为 0,视角偏移约 35°
- 用于从门缝、走廊拐角观察

**屏息(Hold breath)**
- 按住时进入屏息状态
- 自身响度降为 0(完全静默)
- 听觉阈值从 25 降至 8,开启**声纹显示**
- 消耗体力 3/秒
- **屏息期间移动速度限制为蹲行速度的 50%**(允许缓慢移动,不完全禁止——这一点在纯静止方案下会让侦查变成"读地图",破坏节奏)

**声纹显示**
- 屏息期间,所有 `margin > 0` 的声音在屏幕上以方向指示环的形式显示
- 指示方向 = **声音传来的路径入口方向**,不是声源的真实方向。隔壁的动静从门口传来,玩家就该感觉声音来自门口
- 方向角误差 = `(1 − 听觉熟练度系数) × 60°`
- 距离只给模糊分级:很近 / 中等 / 很远
- 不同 `category` 用不同图标区分(脚步 / 撞击 / 低吼 / 枪声)

## 4.3 交互

| 动作 | 快速版 | 缓慢版 |
|---|---|---|
| 开门 | 瞬间,响度 35 | 按住 2.5 秒,响度 12 |
| 翻找容器 | 4 秒,响度 40 | 9 秒,响度 15 |
| 关门 | 瞬间,响度 30 | 按住 2 秒,响度 10 |

**缓慢版是默认应该被鼓励的做法。** 快速版存在的意义是"来不及了"。

**封锁(Barricade)**
- 对门/窗使用建材,将 Portal 状态改为 `Blocked`
- 需要 建材 ×1–3(依 Portal 类型),作业 20–60 秒
- 作业期间持续产生响度 50 的噪音
- 封锁后该 Portal 不可通行、衰减大幅提高
- 可以拆除,拆除同样耗时且吵

## 4.4 投掷

**石头(基础,无限制)**
- 校园内可随处拾取
- 抛物线飞行,落点产生响度 45 的 `Impact` 事件
- 有效引怪半径约 22 米(夜间约 31 米)
- 玩家可以**蓄力调整投掷距离**,按住时显示落点预测弧线

**其他投掷物**

| 物品 | 落点响度 | 特殊 |
|---|---|---|
| 石头 | 45 | 可无限获取 |
| 玻璃瓶 | 75 | 碎裂,吸引范围大 |
| 发令枪(体育器材室) | 110 | 一次性使用,响度极大,是结局二布置阶段的关键道具 |
| 闹钟(可制作) | 60,持续 15 秒 | 定时触发,可以提前布置。**是唯一能做到"延迟引怪"的道具** |

**闹钟是潜行深度的关键。** 它让玩家可以做规划:提前在 A 点放一个 90 秒后响的闹钟,然后自己去 B 点等待。

## 4.5 视觉与被发现

丧尸的视觉:

- 感知锥角 110°,半径 14 米(白天)/ 7 米(夜间)/ 12.6 米(夜间但玩家持灯)
- 玩家蹲下时被发现半径 ×0.6,贴墙探头时 ×0.35
- 有遮挡则完全看不见(用射线检测,每只丧尸每 0.2 秒一次,只对半径内的丧尸执行)
- 进入视野不是立即发现,有一个 **0.8 秒的识别条**,期间玩家可以退回掩体

# 第五部分 · 丧尸

## 5.1 总体设定

- **全校丧尸总数约 320 只,固定,不刷新。**
- 每只丧尸有唯一 ID 和持久状态(位置、健康、当前行为)
- 死亡永久移除
- 未加载区域的丧尸以简化形式模拟(只维护"所属节点 + 目标节点"),玩家进入时还原

## 5.2 类型

只有三种。不要增加。

**游荡者(约 85%)**
- 基础型。在指定区域内缓慢游荡
- 移动 1.0 m/s(游荡)/ 3.2 m/s(追击)
- 生命 100。头部命中伤害 ×4
- 听觉阈值 10,视觉半径 14m

**蜷伏者(约 10%)**
- 静止趴伏在暗处、课桌下、床下、储物柜内。远看像尸体
- 听觉阈值 6(比游荡者敏感),但只有当声音源在 8 米内才起身
- 起身后与游荡者相同
- **作用是让玩家不敢放松地穿过看似安全的房间**
- 屏息时能听到它们极轻微的呼吸声(响度 12 的持续 `Ambient` 事件)——**这是屏息作为侦查工具的核心价值**

**奔行者(约 5%,第 12 天后才出现在部分区域)**
- 移动 5.4 m/s,比玩家快
- 生命 60(更脆)
- 听觉阈值 6,视觉半径 18m
- **不能靠跑摆脱,只能靠拐角断视线或提前避开**
- 第 12 天前完全不出现,作为难度递进的标志

## 5.3 感知与反应

完整规则见《声音系统规格》第 5 节。摘要:

```
margin = 到达响度 − 听觉阈值

margin ≤ 0        → 无反应
反应延迟(秒)      = clamp(3.0 − margin × 0.06, 0.1, 3.0)
定位误差半径(米)   = clamp(12.0 − margin × 0.25, 0.0, 12.0)
```

目标点偏移在**接收事件时确定一次并固定**,不每帧重算。

## 5.4 行为状态机

```
游荡 ──听到声音──> 警觉(转向,延迟) ──延迟结束──> 调查(走向目标点)
                                                    │
调查 ──到达目标点──> 搜索(原地徘徊 8~15 秒) ──超时──> 返回游荡
                                                    │
任意状态 ──看见玩家(识别条满)──> 追击 ──失去目标 6 秒──> 搜索
```

**追击时丧尸持续发出响度 55 的低吼**——这会引来更多丧尸。这是本作最危险也最刺激的机制。

## 5.5 连锁警戒的上限

追击低吼会引发连锁。为避免雪崩失控:

- 单次连锁最多传播 **2 层**(A 引来 B,B 引来 C,C 不再引人)
- 同时处于追击状态的丧尸全场上限 **12 只**;超过时最远的转为搜索状态
- 这两个数字必须可配置

## 5.6 尸群迁移事件

第 15、21、26 天各触发一次(可配置)。

- 全校丧尸的游荡区域重新分配
- 玩家熟悉的路线可能变得危险,原本危险的区域可能空出来
- 迁移当天有明显预兆:清晨大量丧尸同向移动,可以从窗口看到
- **迁移不产生新丧尸,只是重新分布**

# 第六部分 · 幸存者

## 6.1 设计约束

**不做跟随 AI,不做战斗 AI,不做寻路跟随。** 幸存者是固定在位置上的 NPC。这是为了让这个系统在单人开发的预算内可实现。

## 6.2 四名幸存者

| 代号 | 位置 | 需求 | 招募后提供 |
|---|---|---|---|
| 老周(保安) | 保安室内间(反锁) | 抗生素 ×1 + 食物 ×3 | 夜间据点警戒:睡眠不再被 margin<30 的声音中断 |
| 小林(学生) | 图书馆书库夹层 | 水 ×4 + 证明外面安全(带她看到清空的路线) | 协助搬运:负重上限 +8kg |
| 陈老师(物理) | 实验楼准备室 | 食物 ×2 + 手电 ×1 | 解锁「修理」配方,发电机故障率降低 |
| 医务室的人(未知姓名) | 医务室(藏在药柜后) | 只需找到并说话 | 可治疗骨折、加速感染治疗 |

## 6.3 招募流程

1. **发现**:通过环境线索(墙上的字条、反锁的门后传来的声音、笔记本记录)
2. **接触**:靠近后触发对话。幸存者说明自己的需求
3. **满足需求**:带来指定物品或完成条件
4. **迁移**:幸存者自行前往据点(过场处理,不做实际寻路),此后固定在据点某个位置

## 6.4 幸存者与结局

- 结局二需要 ≥3 名
- 结局一中,幸存者会参与最后三夜的守城(表现为:被他们守住的入口不会被突破)
- 结局三(车辆)可以带走所有已招募的幸存者。徒步逃离**不能带走任何人**——这是它成为"最差结局"的原因

# 第七部分 · 物资、背包与制作

## 7.1 背包(格子系统)

**格子背包,参考《三角洲行动》的形式。**

| 容器 | 尺寸 | 获取 |
|---|---|---|
| 斜挎包 | 4×3 = 12 格 | 初始 |
| 学生书包 | 5×4 = 20 格 | 宿舍楼/教学楼常见 |
| 战术背包 | 6×5 = 30 格 | 保安室,唯一 |
| 登山包 | 6×6 = 36 格 | 体育器材室,唯一 |

**快取位:** 上衣口袋 1×2、裤子口袋 2×2,始终可用,不依赖背包。放在快取位的物品可以用数字键直接使用。

**负重独立于格子。** 基础负重上限 20kg。

```
负重比 r = 当前重量 / 上限

脚步响度 × (1 + 0.5r)
体力消耗 × (1 + 0.8r)
奔跑速度 × (1 − 0.25r)
```

超过上限 100% 时无法奔跑。**背得多就吵、就累、就慢**——这是支柱一在物资系统上的体现。

## 7.2 物资分布原则

- **完全手工放置,不做随机生成。** 玩家的地图知识是跨局的核心资产,随机化会摧毁它
- **不刷新。** 拿走就没了
- 数量按"精打细算能撑到 30 天,浪费则撑不到 20 天"标定

**主要物资点:**

| 地点 | 主要产出 |
|---|---|
| 宿舍楼 | 零食、瓶装水、衣物、书包、少量药品 |
| 食堂 | 米面粮油(大量,但需要烹饪)、炊具、燃气 |
| 小卖部 | 零食、饮料、打火机、电池 |
| 医务室 | 绷带、消毒、**抗生素(全校仅 4 支)** |
| 实验楼 | 酒精、化学试剂、玻璃器皿、烧杯(可煮水) |
| 保安室 | 钢叉、警棍、手电、对讲机、校园平面图、战术背包 |
| 体育器材室 | 棒球棍、发令枪、登山包、绳索 |
| 教学楼 | 零散文具、少量食物、闹钟零件 |
| 图书馆 | 书籍(解锁配方)、安静(适合做据点) |
| 车棚 | 车辆零件、工具 |
| 锅炉房 | 柴油、发电机、工具 |
| 行政楼 | 钥匙、广播设备、信标 |

## 7.3 水系统

**这是第二幕的核心矛盾。**

- 第 1–7 天:水龙头可用,无限接水(但每次接水响度 30,且需要容器)
- **第 8 天 00:00,自来水停供。** 所有水龙头失效
- 此后水的来源:
  1. **瓶装水**:有限,分布在各处,总量约够 6 天
  2. **雨水收集**:需要制作雨水收集器(容器 + 塑料布),放在露天处。**下雨天才有产出**
  3. **可疑水源**:消防水箱、水池、马桶水箱。未处理直接喝有 40% 概率腹泻,煮沸后安全
  4. **煮沸**:需要热源(食堂燃气灶 / 酒精灯 / 篝火)+ 容器。耗时 3 游戏小时,产生响度 20 的持续噪音

**天气:** 30 天中安排 6 个雨天(第 9、13、17、22、25、28 天)。雨天特性:
- 雨声掩盖脚步(全局玩家响度 −30%),**是最适合行动的日子**
- 但视野降低,且丧尸也更难被听见
- 是唯一的雨水收集窗口
- 天气必须是**固定的,不随机**——玩家应该能提前规划

## 7.4 烹饪

**热源:** 食堂燃气灶(最好)、酒精灯(实验楼)、篝火(可制作,但响度和光都很大)

**基础配方(初始可用):**

| 配方 | 材料 | 饥饿恢复 | 备注 |
|---|---|---|---|
| 煮水 | 水 + 容器 | — | 净化可疑水 |
| 白饭 | 米 + 水 | 30 | |
| 泡面 | 泡面 + 热水 | 25 | |
| 煮鸡蛋 | 鸡蛋 + 水 | 18 | |

**熟练度解锁配方:** 见 8.5。高级配方饥饿恢复更高、且部分提供 buff(例如「热汤」提供 2 小时的保暖,降低夜间体力消耗)。

**烹饪的代价:** 每次烹饪持续 20–40 分钟游戏时间,期间产生响度 25 的持续噪音,并且**产生气味**——气味不做复杂模拟,简化为:烹饪结束后 1 游戏小时内,该节点及相邻节点的丧尸听觉阈值 −3。

## 7.5 制作

制作需要**工作台**(可在据点搭建,需要 工具 ×1 + 建材 ×2)。

| 物品 | 材料 | 需要熟练度 |
|---|---|---|
| 绷带 | 布 ×2 | — |
| 建材 | 木板/课桌 + 工具 | — |
| 闹钟 | 闹钟零件 ×2 + 电池 | 手艺 2 |
| 雨水收集器 | 容器 + 塑料布 + 建材 | 手艺 1 |
| 消音布(缠鞋) | 布 ×3 | 手艺 2,静步响度 −15% |
| 长柄武器加固 | 武器 + 建材 + 工具 | 手艺 3 |
| 修理零件 | 废零件 ×3 + 工具 | 手艺 3 |

# 第八部分 · 战斗、伤势与熟练度

## 8.1 武器

**近战为主。武器稀少。** 第一幕基本没有武器。

| 武器 | 获取 | 伤害(头/身) | 挥击响度 | 体力 | 耐久 |
|---|---|---|---|---|---|
| 拖把杆 | 宿舍楼 | 25 / 8 | 40 | 5 | 30 |
| 棒球棍 | 体育器材室 | 55 / 20 | 55 | 6 | 80 |
| 消防斧 | 各楼消防箱 | 90 / 40 | 65 | 10 | 60 |
| 钢叉 | 保安室 | 40 / 15 | 50 | 7 | 120 |
| 警棍 | 保安室 | 45 / 18 | 45 | 5 | 150 |
| 菜刀 | 食堂 | 60 / 25 | 35 | 4 | 40 |

**没有枪。** 一所中国学校不该有枪。发令枪是纯噪音道具,不造成伤害。这个限制是设计上的优势——它保证了游戏永远不会变成射击游戏。

## 8.2 战斗规则

- 攻击有前摇(0.4–0.9 秒,依武器),**期间不能取消**
- 背后偷袭:对未察觉的丧尸从背后攻击,**必定处决**,响度只有 30,不消耗耐久
- 处决是玩家清理丧尸的主要手段。正面战斗几乎总是错误选择
- 正面被丧尸抓住 → 进入挣脱 QTE,失败则被咬
- 同时被 2 只以上丧尸接触 → 必然被咬

## 8.3 伤势系统

**死亡不应该是瞬间的。** 玩家应该有机会犯错并挽回,但要付出代价。

| 伤势 | 来源 | 效果 | 治疗 |
|---|---|---|---|
| 出血 | 被抓、被咬 | 每秒 −0.8 生命,持续至处理 | 绷带 |
| 骨折 | 高处跌落、被扑倒 | 移动速度 −40%,奔跑时每秒产生响度 50 的痛呼 | 夹板 + 静养 12 小时,或医务室幸存者 |
| 感染 | 被咬,**60% 概率** | 潜伏 6 小时后开始:每小时生命上限 −3,累积至死 | **抗生素**(全校 4 支),或医务室幸存者 + 酒精(成功率 60%) |
| 腹泻 | 喝未处理的水 | 口渴增速 ×2,持续 8 小时 | 自愈或药物 |

**抗生素只有 4 支,而感染概率是 60%。** 这意味着玩家最多能承受约 6 次被咬。这个数字定义了整局游戏的容错额度。

## 8.4 死亡

- 生命值归零 → 死亡
- 死亡 → 存档删除 → 返回主菜单
- 无复活、无检查点

**建议(待你拍板):** 增加一个「幸存者笔记」的跨局继承。死亡后,本局中你**已探索过的地图区域、已发现的配方、已见过的丧尸类型**会留在一本笔记里,新一局开始时可查阅。它**不提供任何数值优势**,只是省去重复摸索。

理由:一局 10 小时以上的永久死亡,如果每次都要从零重新摸清地图布局,大部分玩家在第二次死亡后会退坑。而地图知识本来就是"玩家脑子里的东西",把它写下来不改变难度,只是减少重复劳动。

这个功能可以做成开关,默认开启,硬核玩家可以关掉。

## 8.5 熟练度

六项技能,各 1–5 级。**使用中成长,但只有有意义的使用才计入。**

### 反刷分设计(重要)

不要按"行为次数"给经验。按"有效行为"给:

- **静步**:只有在**某只丧尸的听觉范围内**成功移动而未被察觉,才计经验。原地蹲着绕圈不给经验
- **听觉**:只有在屏息状态下,声纹指向了一个**之前未知的丧尸**,才计经验
- **体能**:只在体力降至 30% 以下时的行动计经验
- **敏捷**:只在被追击状态下的翻越、冲刺计经验
- **烹饪**:每个配方**首次**制作给大量经验,重复制作给递减经验(第 5 次后归零)
- **手艺**:同烹饪,按配方计

### 等级效果

| 技能 | Lv1 | Lv2 | Lv3 | Lv4 | Lv5 |
|---|---|---|---|---|---|
| **静步** | 响度 −8% | −16% | −24%,解锁"极慢步"(速度 0.6m/s,响度 4) | −32% | −40%,蹲行时不再触发地面杂物声 |
| **听觉** | 方向误差 −15% | −30%,声纹显示丧尸类型 | −45% | −60%,声纹穿透一层 Portal 显示 | −75%,近乎精确定位 |
| **体能** | 体力上限 +10 | +20,奔跑消耗 −10% | +30,困乏增速 −10% | +40,消耗 −20% | +50,体力耗尽不再产生喘息声 |
| **敏捷** | 奔跑速度 +5% | +10%,翻越更快 | +15%,解锁攀爬管道 | +20% | +25%,跌落不再骨折 |
| **烹饪** | 恢复量 +10% | +20%,解锁 3 个配方 | +30%,食物不易腐 | +40%,解锁 3 个配方 | +50%,解锁 buff 类食物 |
| **手艺** | 搜刮速度 +15% | +30%,解锁闹钟 | +45%,解锁修理 | +60%,封锁作业更快更安静 | +75%,武器耐久消耗减半 |

所有效果通过数值修正管线生效。**技能等级不写进任何业务逻辑,业务逻辑只向管线要最终值。**

## 9.3 出生点

宿舍 402。四楼,离楼梯口中间位置。宿舍楼在校园最深处,距离所有校门最远。

## 9.5 场景加载

# 第十部分 · 界面

## 10.1 HUD(常驻)

尽可能少。屏幕上只有:

- **左下:生命条**(含饥饿/口渴挤占段,颜色区分)
- **左下:体力条**(含困乏挤占段)
- **右下:手中物品 + 快取位**
- **屏息时:声纹指示环**(非屏息时不显示)
- 时间**不常驻显示**。玩家按键查看手表,或通过天色判断

伤势、负重等信息不在 HUD 常驻,通过背包界面查看。

## 10.2 背包界面

- 格子网格 + 拖拽
- 左侧:角色装备槽(背包、武器、衣物)
- 右侧:容器内容(搜刮时)
- **打开背包时游戏不暂停。** 搜刮和整理背包本身就是有风险的行为

## 10.3 笔记本

被动记录,分四页:

- **地图**:已探索区域的手绘平面图,玩家可以手动标记
- **线索**:发现的字条、广播内容、幸存者信息
- **配方**:已解锁的烹饪与制作配方
- **观察**:关于丧尸的记录(见过的类型、行为规律)

## 10.4 暂停菜单

ESC 呼出,**游戏暂停**。可以保存并退出。

**不能在暂停菜单里读档。** 存档只在启动游戏时加载一次。

# 第十一部分 · 技术架构

## 11.1 分层

严格单向依赖。下层不得引用上层。

```
第 5 层  流程层     结局判定 · 幸存者 · 事件调度(尸群迁移/天气/广播)
                    ↓ 只能向下依赖
第 4 层  交互层     背包 · 搜刮 · 制作 · 烹饪 · 战斗 · 投掷 · 封锁
                    ↓
第 3 层  实体层     玩家控制器 · 丧尸 AI · 听觉组件 · 伤势
                    ↓
第 2 层  规则层     声音传播 · 生存需求 · 熟练度 · 天气
                    ↓
第 1 层  地基层     游戏时钟 · 事件总线 · 数值修正管线 · 数据资产 · 存档序列化 · 地图图数据
```

**判断依据:** 如果 A 系统删掉后 B 系统还能编译,那 B 不依赖 A。检查每一层是否满足这个条件。

## 11.2 事件总线

所有跨系统通信走事件。事件是不可变的结构体。

```csharp
public interface IGameEvent { }

public static class EventBus {
    public static void Subscribe<T>(Action<T> handler) where T : IGameEvent;
    public static void Unsubscribe<T>(Action<T> handler) where T : IGameEvent;
    public static void Publish<T>(T evt) where T : IGameEvent;
}
```

**核心事件清单:**

| 事件 | 发出者 | 主要订阅者 |
|---|---|---|
| `SoundEmitted` | 任何发声行为 | 声音系统 |
| `SoundHeard` | 声音系统 | 听觉组件(丧尸 AI / 玩家 UI) |
| `PortalStateChanged` | 门/窗交互、封锁 | 声音系统(缓存失效) |
| `HourPassed` | 游戏时钟 | 需求、天气、流程调度 |
| `DayPassed` | 游戏时钟 | 流程调度 |
| `NeedChanged` | 需求系统 | UI |
| `PlayerDamaged` / `PlayerInjured` | 伤势系统 | UI、音效 |
| `ZombieDied` | 战斗 | 流程层(结局二计数) |
| `ItemAcquired` / `ItemConsumed` | 背包 | 笔记本、熟练度 |
| `SkillLeveled` | 熟练度 | 修正管线、UI |
| `SurvivorRecruited` | 幸存者 | 流程层、修正管线 |
| `ObjectiveProgressed` | 流程层 | 笔记本、UI |

**约束:** 事件处理器不得在处理过程中发出会导致同类事件递归的事件。深度超过 8 层时记录警告。

## 11.3 数值修正管线

所有可变数值的唯一出口。

```csharp
public static class ModifierPipeline {
    // key 例: "sound.footstep", "hearing.threshold", "stamina.run_cost"
    public static float Query(string key, float baseValue, int ownerId);

    public static void Register(string key, IModifier modifier);
    public static void Unregister(string key, IModifier modifier);
}

public interface IModifier {
    int Priority { get; }        // 低的先执行
    ModifierMode Mode { get; }   // Additive / Multiplicative / Override
    float Apply(float current, int ownerId);
}
```

**执行顺序:** 先全部 Additive,再全部 Multiplicative,最后 Override(若有)。

**修正来源:** 熟练度、装备、负重、伤势、buff、幸存者加成、天气。全部注册到同一个管线。

**这是整个架构里最重要的抽象。** 它意味着以后加任何新的加成来源,都不需要改动任何原有系统。

## 11.4 数据资产

所有静态配置用 ScriptableObject,不写在代码里。

- `ItemDefinition` — 物品(尺寸、重量、堆叠、效果)
- `RecipeDefinition` — 配方
- `WeaponDefinition` — 武器
- `ZombieTypeDefinition` — 丧尸类型
- `SkillDefinition` — 技能与各级效果
- `PortalTypeTable` — 连接类型衰减表
- `LoudnessTable` — 行为响度表
- `GameBalanceConfig` — 全局数值(时间比例、需求速率、衰减系数等)

**所有第三部分到第八部分出现的数字,都必须存在于某个数据资产中,不得硬编码。**

## 11.5 存档

**单存档,随时保存,死亡删除。**

需要序列化的内容:

- 游戏时间(天/时/分)
- 玩家:位置、朝向、生命、体力、需求值、伤势、熟练度经验、背包内容、装备
- 所有丧尸:ID、类型、位置、生命、行为状态、目标点
- 所有 Portal 的 state
- 所有物资容器的剩余内容(记录"已被拿走什么",不是记录全部内容)
- 已招募幸存者、已完成的结局前置条件
- 笔记本内容、已解锁配方
- 天气与事件调度进度

**格式:** JSON(便于调试)。加载在启动时一次性完成。

**版本号必须写入存档头**,不兼容时明确提示而不是崩溃。

## 11.6 命名规范

- 类型:`PascalCase`
- 私有字段:`_camelCase`
- ScriptableObject 资产文件:`SO_<类别>_<名称>`
- 事件类型:以 `Event` 结尾,如 `SoundEmittedEvent`
- 修正管线的 key:小写点分,如 `sound.footstep`
- 数值配置字段名与本文档中的表格列名保持一致

## 11.7 性能预算

| 项 | 预算 |
|---|---|
| 单次声音传播 | < 0.5 ms |
| 声音事件峰值 | 40 次/秒 |
| 同时活跃的丧尸 AI | 60 只 |
| 简化模拟的丧尸 | 260 只,每 2 秒更新一次 |
| 目标帧率 | 60 FPS(中端 PC) |

# 第十三部分 · 待定与风险

## 13.1 需要决策的问题

1. **幸存者笔记(跨局继承)是否实装?** 见 8.4。我建议实装并默认开启。
2. **白天时长 17 分钟是否足够?** 建议 M1 完成后立即实测,备选 20/22 分钟。
3. **丧尸追击低吼的连锁上限**(2 层 / 12 只)需要实测校准。
4. **玩家能否听见丧尸的常态呼吸?** 本文档假定"是"(蜷伏者有响度 12 的呼吸声)。若实测发现噪音太杂,可改为只有蜷伏者有。

## 13.2 已识别的风险

**风险一:单局时长过长。** 30 天 × 34 分钟约 17 小时,即使跳过夜晚也在 10 小时以上。配合永久死亡,劝退风险高。
缓解:幸存者笔记 + 伤势系统提供的容错 + 结局三随时可用作为"止损出口"。
若实测确实过长,**优先考虑压缩到 20 天而不是缩短单日时长**——单日 17 分钟已经很紧。

**风险二:结局二的执行段落难度可能失控。** 4 分钟被全校丧尸追赶,一次失败就是一局。
缓解:执行前给明确警告与准备清单;考虑允许"演习模式"(不开广播,仅测试路线跑通时间)。

**风险三:声音系统的调试成本。** 玩家听不见的东西很难 debug。
缓解:**必须在 M0 就做一个可视化调试工具**——按键切换到俯视图,实时显示每个节点的当前响度、每只丧尸的 margin 和目标点。这个工具的开发时间是值得的。

**风险四:手工布置物资的工作量。** 全校数百个容器全部手工填内容,是巨大的重复劳动。
缓解:做一个"物资池"系统——按房间类型定义产出池和数量范围,编辑器里一键生成初始布置,再手工调整关键点。**生成结果落盘为固定数据,不在运行时随机。**
