# 第零部分 · 给实现者的说明

## 0.1 怎么用这份文档

**新开一个对话时，先贴第零部分和第一部分（架构），那是硬约束；然后说「实现 X 系统」。**

每个系统章节的结构是固定的：**规则 → 数值表 → 已知结论 → 待决策**。
「已知结论」是实测得出的、文档 v1 里没有的事实；「待决策」是还需要人拍板的地方。

## 0.2 硬性约束（任何时候不能违反）

1. **分层依赖单向。** 下层不得知道上层的存在、不得引用上层类型。分层见 1.1。
2. **系统之间不直接调用，通过事件总线通信。** 唯一例外是向下查询（上层可读下层的只读接口）。
3. **任何游戏数值在使用前必须经过数值修正管线。** 不要在业务代码里写死数字。
4. **所有运行时状态必须可序列化。** 存档是随时保存，不是检查点保存。
5. **不要发明文档里没有的机制。** 有疑问就留 TODO 并报告，不要自行补全。
6. **每个数字都要能回答「这个数是怎么来的」。** 本文档中标注：
   `[实测]` 已在原型上验证 · `[推导]` 由其他数值算出 · `[占位]` 尚无依据，待实测。

## 0.3 数值标注的含义

| 标注 | 含义 | 改动它的条件 |
|---|---|---|
| `[实测]` | 原型上跑过，手感或平衡已验证 | 需要重新实测 |
| `[推导]` | 由公式和其他数值算出，不是独立参数 | 改上游参数即可，不要直接改它 |
| `[占位]` | 文档 v1 未定义，实现时临时填的 | 随时可改，改前请补测试 |

## 0.4 遇到冲突

以**更靠后的章节**为准，并报告矛盾点。

# 第一部分 · 技术架构（硬约束）

## 1.1 分层

严格单向依赖。判断依据：**如果 A 系统删掉后 B 还能编译，那 B 不依赖 A。**

```
第 5 层  流程层   结局判定 · 幸存者 · 事件调度（尸群迁移/天气/广播）
                  ↓ 只能向下依赖
第 4 层  交互层   背包 · 搜刮 · 制作 · 烹饪 · 战斗 · 投掷 · 封锁 · 睡眠 · 新手教学
                  ↓
第 3 层  实体层   玩家控制器 · 丧尸 AI · 听觉组件 · 伤势
                  ↓
第 2 层  规则层   声音传播 · 生存需求 · 熟练度 · 天气 · 供电（回路/跳闸/燃料）
                  ↓
第 1 层  地基层   游戏时钟 · 事件总线 · 数值修正管线 · 数据资产 · 存档序列化 · 地图图数据
```

**第 1–3 层必须能脱离渲染引擎运行。** 原型里这一点是靠「零 UnityEngine 引用」做到的，
所有规则都能在纯 CLI 下跑单元测试。这不是洁癖，是唯一能在改数值时不引入回归的办法。

## 1.2 事件总线

```csharp
public interface IGameEvent { }
public static class EventBus {
    public static void Subscribe<T>(Action<T> handler) where T : IGameEvent;
    public static void Unsubscribe<T>(Action<T> handler) where T : IGameEvent;
    public static void Publish<T>(T evt) where T : IGameEvent;
}
```

| 事件 | 发出者 | 主要订阅者 |
|---|---|---|
| `SoundEmitted` | 任何发声行为 | 声音系统、音效 |
| `SoundHeard` | 声音系统 | 听觉组件（丧尸 AI / 玩家 UI） |
| `PortalStateChanged` | 门窗交互、封锁 | 声音系统（缓存失效）、渲染 |
| `HourPassed` / `DayPassed` | 游戏时钟 | 需求、天气、流程调度 |
| `NeedChanged` | 需求系统 | UI |
| `PlayerDamaged` / `PlayerInjured` | 伤势系统 | UI、音效 |
| `ZombieDied` | 战斗 | 流程层（结局二计数） |
| `ItemAcquired` / `ItemConsumed` | 背包 | 笔记本、熟练度 |
| `SkillLeveled` | 熟练度 | 修正管线、UI |
| `SurvivorRecruited` | 幸存者 | 流程层、修正管线 |
| `ObjectiveProgressed` | 流程层 | 笔记本、UI |

**约束：** 处理器不得发出会导致同类事件递归的事件。深度超过 8 层记录警告。

## 1.3 数值修正管线

所有可变数值的唯一出口。**这是整个架构里最重要的抽象** —— 以后加任何新的加成来源，
都不需要改动任何原有系统。

```csharp
public static class ModifierPipeline {
    public static float Query(string key, float baseValue, int ownerId);
    public static void Register(string key, IModifier modifier);
    public static void Unregister(string key, IModifier modifier);
}
public interface IModifier {
    int Priority { get; }        // 低的先执行
    ModifierMode Mode { get; }   // Additive / Multiplicative / Override
    float Apply(float current, int ownerId);
}
```

**执行顺序：先全部 Additive，再全部 Multiplicative，最后 Override。**

**⚠ 实测教训：** 屏息最初写成 Override（把听觉阈值直接覆盖为固定值），
结果**听觉熟练度的收益被一笔抹掉** —— 练到 Lv5 和 Lv0 屏息后一样。
凡是「在当前值上再改善一点」的效果，必须用 Additive/Multiplicative，不能用 Override。
Override 只用于「无视一切，就是这个值」的场合。

**修正来源：** 熟练度、装备、负重、伤势、buff、幸存者加成、天气。全部注册到同一管线。

**已在用的 key：**
`sound.footstep` · `hearing.threshold` · `hearing.localization` · `stamina.run_cost` ·
`stamina.climb_cost` · `stamina.jump_cost` · `hold_breath.stamina_cost` · `move.run_speed`

## 1.5 存档

**单存档、随时保存、死亡删除、JSON、版本号写进存档头**，不兼容时明确提示而不是崩溃。

需要序列化：游戏时间 · 玩家（位置/朝向/生命/体力/需求/伤势/熟练度经验/背包/装备）·
所有丧尸（ID/类型/位置/生命/行为状态/目标点）· 所有 Portal 状态 ·
物资容器的**已被拿走什么**（不是记录全部内容）· 已招募幸存者 · 已完成的结局前置 ·
笔记本内容 · 已解锁配方 · 天气与事件调度进度。

`[实测]` **Portal 只记录与出厂状态不同的那些。** 存档体积小一个数量级，
而且改了地图之后旧存档仍能读进来（多出来的 Portal 用出厂值）。

`[实测]` 同一条思路贯穿全部集合类状态：**只存与「按固定种子重新生成」不同的部分。**

| 状态 | 存什么 |
|---|---|
| 容器 | 只存 `opened` 过的（id + 已点亮数 + 格子布局）；没翻过的重新生成即可 |
| 地上散落物 | 只存被拿走的那几个的下标 |
| 背包 | **连格子坐标和旋转一起存**，否则读档后拼图全乱 |
| 丧尸 | ID/类型/位置/朝向/生命/状态/目标点（数量不符时以存档为准） |
| 笔记本 | 走过的节点 id、进过的楼、翻过的容器、线索、配方、观察、手动标记 |

存档版本号随结构变更递增（当前 **v2**：加了背包/容器/笔记本），
读到旧版本**明确提示并忽略**，不做迁移 —— 开发期的存档不值得写迁移代码。

# 第二部分 · 设计支柱

这四条决定所有取舍。**当某个设计选项与支柱冲突时，砍掉这个选项。**

### 支柱一：声音是唯一的通货
玩家的每个动作都有噪音代价。跑得快就吵，搜得快就吵，砸门就更吵。
**推论：** 任何新机制加入前先问——它有噪音代价吗？没有的话，它凭什么存在？

### 支柱二：世界是有限的，并且会被永久改变
丧尸有限、物资有限、不刷新。今天清掉的走廊明天真的是空的。
**推论：** 不做任何形式的刷新式重复内容。

### 支柱三：玩家应该能在脑内推演
声音传播、丧尸反应、需求消耗速率全部是确定性的。没有隐藏的随机数决定生死。
**推论：** 死亡永远是玩家能复盘的。「我不该那时候跑」而不是「我运气不好」。
**实现要求：** 一切随机（定位误差、腹泻概率、游荡目标）必须走**可复现的种子随机数**，
不能用系统 Random —— 否则存档读档后世界会变，玩家的推演就白费了。

### 支柱四：三十天是一条下坡路
难度不来自敌人变强，来自资源变少、水源断绝、丧尸重新分布。


`[实测]` 全校地图（13 栋楼 / 298 节点 / 553 Portal / 320 只丧尸）实测的每帧开销：

| 项目 | 每帧 | 占 60fps 预算(16.7ms) |
|---|---|---|
| **声音传播** | **0.03 ms** | **0.18%** |
| 320 只丧尸的全部逻辑（含听觉） | 1.36 ms | 8% |
| 渲染绘制 | 1.19 ms | 7% |
| 渲染更新 / HUD / 玩家 / 分区加载 / 笔记本 | 各 0.007~0.10 ms | 可忽略 |
| 俯视调试图（Tab，限流前） | **5.79 ms** | **35%** |
| 俯视调试图（限到 20fps 后） | 1.90 ms | 11% |

**声音系统不是负担。** 全场每游戏秒只发出约 **35 次**声音事件，
每帧平均 1.2 次传播、单次 0.001ms —— 它只占丧尸开销的 3%，
比渲染一帧的零头还少。原因见 3.4：Dijkstra 展开的是**节点**（298 个）而不是网格，
而且响度一旦衰减到阈值以下就停止展开，实际展开的节点数只有几十个。

`[实测]` 真正贵的是**俯视调试图**：整幅重画一次 5.8ms，比 320 只丧尸的全部逻辑还贵四倍。
它是开发工具，不该跟渲染抢帧预算 —— 限到 20fps 重画，摊下来 1.9ms，肉眼看不出区别。

## 2.1 一句话与核心循环

你是唯一一个睡过头的学生。醒来时，学校已经不是学校了。

```
白天：规划 → 潜行外出 → 搜刮/推进目标 → 天黑前返回据点
夜晚：处理需求（吃/喝/做饭/治伤）→ 睡觉 → 或冒险夜行
```

玩家反复做的那件事：**在有限的时间和噪音预算内，决定今天去哪、拿什么、什么时候撤。**

## 2.2 三幕

| 幕 | 天数 | 主题 | 玩家状态 |
|---|---|---|---|
| 一 | 1–5 | 求生 | 只有宿舍楼。任何一只丧尸都是致命威胁 |
| 二 | 6–18 | 立足 | 走出宿舍楼。解决水与食物，获得第一件武器，发现三条结局线索 |
| 三 | 19–30 | 抉择 | 物资枯竭，尸群迁移。选定一个结局全力推进 |

**第 8 天自来水停供**是一幕到二幕的推力。**第 15 天首次尸群迁移**是二幕到三幕的推力。

# 第三部分 · 声音系统（核心规则层）

> 这是全作的地基。潜行、丧尸 AI、昼夜、投掷、静步与听声熟练度全部建立在它之上。
> 它必须在其他系统之前实现，且不依赖任何上层系统。

## 3.1 它知道什么、不知道什么

**知道：** 一张地图连通图、一个只读游戏时钟、一个数值修正管线。
**不知道：** 丧尸、玩家、背包、UI 的存在。所有听者通过统一的 `HearingComponent` 接入。

## 3.2 核心公式

```
到达响度 = 源响度 − 距离衰减系数 k × 路径长度 − Σ(路径上所有 Portal 的衰减)
```

**路径长度是声音实际绕行的距离，不是直线距离。**

| k | 值 | 说明 |
|---|---|---|
| 室内 | 2.0 / 米 | |
| 室外 | 1.2 / 米 | 开阔地衰减更慢 |
| 夜间 | 全局 × 0.7 | 声音传得更远，等效距离 +43% |

夜间系数从时间系统读取，**必须是随时间平滑变化的曲线**，避免 19:00 整点声音突然变远。

## 3.3 数据结构

**`SoundEvent`**（发出后不可变）：`worldPosition` · `nodeId` · `loudness`(0–150) ·
`category`(Footstep/Impact/Voice/Gunshot/Ambient/Door) · `emitterId`(-1=无主) ·
`timestamp` · `chainDepth`(连锁层数)

`category` **不影响传播**，只影响听者的解读（UI 图标、丧尸对 Voice 的特殊处理）。

**`SoundNode`**：`id` · `bounds` · `isOutdoor` · `buildingId` · `floor` · `portals[]`

**`SoundPortal`**：`id` · `nodeA/nodeB` · `position` · `type` · `state` · `attenuation`(查表)

**`state` 是运行时可变的。** 玩家关门 → 木门衰减从 5 变 45。这是玩家控制声音传播的
主要手段，也是整个潜行玩法的核心交互。状态变化必须发 `PortalStateChanged` 让缓存失效。

**`HearingComponent`**：`threshold` · `localizationSkill` · `selfEmitterId`
**丧尸和玩家共用同一个组件。** 这是本系统最重要的架构决策——避免两套并行的听觉逻辑不一致。

## 3.4 传播算法

在 Portal 图上跑 **Dijkstra**，代价 = 累计衰减量。

```
1. 起始节点的入口点 = 声源位置本身，累计衰减 = 0
2. 优先队列按累计衰减升序展开
3. 从节点 N 经 Portal P 到节点 M：
     段长 = distance(N的入口点, P.position)
     新累计衰减 = 当前累计 + k × 段长 + P.attenuation
4. 剪枝：若 源响度 − 新累计衰减 < GLOBAL_MIN_THRESHOLD，不再展开
5. 每个节点只保留衰减最小的那条路径（自动实现「多通道取最优」）
```

`GLOBAL_MIN_THRESHOLD` = 全场景所有听者阈值的最小值。**这个剪枝是性能的关键。**

**听者结算**（图搜索只给到节点入口，还要加节点内的最后一段）：

```
若 听者节点 == 声源节点：到达响度 = 源响度 − k × distance(声源, 听者)
否则：              到达响度 = 该节点入口响度 − k × distance(入口Portal, 听者)
```

这一步解决了纯图模型的最大缺陷：**同一房间内贴脸和隔十米不再等价。**

**结算时机：** 事件驱动，不在 Update 里轮询。事件发出 → 立即跑一次传播 → 推给受影响节点内的听者。

## 3.5 边界情况

| 情况 | 处理 |
|---|---|
| 未加载区域 | **Portal 图始终全量常驻内存**（几百节点，几十 KB，不含美术）。传播不受加载状态影响 |
| 跨楼栋 | 正常走图。楼与楼通过室外节点相连，大门/破窗作为 Portal。枪声传遍半个校园是正确行为 |
| 室外传播 | 室外按功能区切成大节点，相邻用 `OpenAir`(衰减0) 连接。同节点内若有建筑遮挡，**额外扣 25**，射线判定 |
| 移动声源 | 脚步是离散事件，每步发一次。跑 0.35s / 走 0.7s 一次 |
| 自己的声音 | 按 `emitterId` 过滤自己的声纹显示，但**仍然会被丧尸听见** —— 否则潜行没有意义 |

`[实测]` **室外遮挡的射线判定必须由外部注入**（装配层传一个纯函数进来）。
声音系统属于规则层，不能反过来依赖碰撞世界，否则分层就破了。

## 3.7 连接类型与衰减

| 类型 | Open | Closed | Broken | Blocked |
|---|---|---|---|---|
| 门洞（无门） | 0 | — | — | 60 |
| 木门 | 5 | **45** | 8 | 75 |
| 铁门/防火门 | 6 | 70 | 10 | 95 |
| 玻璃窗 | 8 | 40 | 6 | 70 |
| 楼梯口 | 10 | — | — | 60 |
| 通风口 | 30 | — | — | 80 |
| 室外相邻 `OpenAir` | 0 | — | — | — |
| 软隔断/帘子 | 20 | 25 | — | — |

`Blocked` = 被家具堵死（玩家封锁行为），**同时阻断通行**。
`[实测]` **同一个 Portal 状态同时管声音和通行，不能分成两套数据** ——
否则会出现「门关着但丧尸走得过去」这类几乎无法察觉的 bug。


`[实测]` **关着的木门 45 → 25、关着的窗 40 → 28。** 45 比丧尸脚步(48) 只低 3 点，
等于「关上门就绝对听不见门后有什么」，于是屏息侦查在楼里彻底没用。
这同时是待决策 #2（「关门是零代价的万能解」）的答案：关门仍然很有用
（25 点 ≈ 室内 12.5m 的墙），但不再是绝对屏障。

反向验算说明玩家的潜行保护没有被破坏：

| 玩家动作 | 响度 | 透过关着的门剩下 | 丧尸（阈值10）听得见的距离 |
|---|---|---|---|
| 蹲行 | 10 | −15 | 听不见 |
| 走 | 20 | −5 | **听不见** |
| 翻找 | 40 | 15 | 2.5m |
| 跑 | 45 | 20 | 5m |

也就是说：关上门之后，正常潜行仍然完全安全，**但跑动和翻找会漏出去**。

## 3.8 听者反应

```
margin = 到达响度 − 最终阈值        （margin ≤ 0 直接丢弃事件）

反应延迟(秒)     = clamp(3.0 − margin × 0.06, 0.1, 3.0)
定位误差半径(米) = clamp(12.0 − margin × 0.25, 0.0, 12.0)
```

- 延迟期间：丧尸先停下、转头朝向大致方向，延迟结束才开始移动。
- 目标点 = 真实声源 + 误差半径内的随机偏移，**该偏移在接收事件时确定一次并固定**，
  不要每帧重算，否则丧尸会抖。
- **优先级覆盖：** 已在追某个声音时，新事件的 margin 必须**高出 8 以上**才切换目标。
  否则玩家连续投石会让丧尸原地反复抽搐。

这套公式自然产生了想要的效果：**近处的丧尸几乎立刻扑向准确位置，远处的迟疑几秒后
走向一个模糊方位。不需要为「远近」写特例。**

## 3.9 玩家听觉：范围模型

**⚠ v1 重大修订。** v1 给玩家的阈值是 25、丧尸是 10 —— 玩家的听力比丧尸差一倍多，
与「听力等级提升听力范围」的设定直接冲突。现改为：

```
可听半径 = (声源响度 − 听觉阈值) / k          阈值越低听得越远
```

| 听觉等级 | 阈值 | 丧尸脚步(48) | 追击低吼(55) | 蜷伏者呼吸(12) |
|---|---|---|---|---|
| Lv0 | 8.0 | **20.0m** / 屏息 22.0m | 23.5 / 25.5m | 2.0 / 4.0m |
| Lv1 | 6.8 | 20.6 / 22.6m | 24.1 / 26.1m | 2.6 / 4.6m |
| Lv2 | 5.6 | 21.2 / 23.2m | 24.7 / 26.7m | 3.2 / 5.2m |
| Lv3 | 4.4 | 21.8 / 23.5m | 25.3 / 27.0m | 3.8 / 5.5m |
| Lv4 | 3.2 | 22.4 / 23.5m | 25.9 / 27.0m | 4.4 / 5.5m |
| Lv5 | 2.0 | 23.0 / 23.5m | 26.5 / 27.0m | 5.0 / 5.5m |

- 初始阈值 **8**，只比丧尸的 10 好一点点 —— 玩家不是超人，只是没那么迟钝。
- **屏息在当前等级值上再减 4**（Additive，不是 Override，见 1.3 的教训）。
- 阈值下限 1。
- 对照：丧尸（阈值 10）听见玩家正常走路是 **5m**、奔跑 17.5m。**玩家有先手。**

### 三条实测结论

1. **`[实测]` 范围上限由声源响度决定，不由听力决定。**
   所以等级对「很轻的声音」影响巨大（蜷伏者呼吸 2m → 5m，两倍半），
   对「很响的声音」几乎无所谓（低吼 23.5m → 26.5m）。
   **练听力是为了听见那些几乎没有声音的东西** —— 这是个好性质，不用额外设计。
2. **`[实测]` 常态听不见蜷伏者呼吸。** 2m 的半径抵不过「耳朵在 1.65m、它趴在地上」
   的高度差。必须屏息。
3. **`[实测]` 屏息收益在高等级后封顶**（阈值贴到下限），其价值自然从「听得更远」
   转为「自己完全不发声」。这个转变是免费的。

### 声源响度是怎么定出来的

`[实测]` 丧尸巡逻脚步定 **48**，是按「初始可听 20m」反推的：`(48−8)/2 = 20`。
**瓶颈从来不是「穿墙扣得太多」，而是声源太轻** —— 定 30 时隔一个楼梯口只剩 5.5m，
等于什么都听不见。48 比玩家奔跑（45）还响，这是有意的：**丧尸不在乎自己发出声音，玩家在乎。**

| 场景 | 玩家 Lv0 可听 |
|---|---|
| 同一房间/走廊 | 20.0m |
| 隔一扇**开着**的木门（衰减 5） | 17.5m |
| 隔一个楼梯口（衰减 10） | 15.0m |
| 隔一扇**关着**的木门（衰减 45） | **听不见** |

**关着的门仍然是硬屏障，这一条不能动。**

`[实测]` **屏息加成 4 → 6。** 屏息是专门用来「仔细听」的动作，
代价是几乎不能动（速度 ×0.5）加持续掉体力，收益却只有 2m —— 玩家感觉不到自己按了这个键。

`[实测]` **玩家最容易误解的一点：可听半径是沿路径算的，不是直线。**
实测站在宿舍楼四楼走廊屏息，20m 内有 26 只丧尸，但**只有 6 只在同一层**；
另外 20 只在楼上楼下，声音得绕到走廊尽头的楼梯间再折回来，路径长度轻松超过 50m。
这不是 bug，是「声音不穿楼板」的正确结果 —— 但界面必须把它说出来，
否则玩家只会觉得「声纹时灵时不灵」。所以屏息时 HUD 直接写两个数：
畅通路径能听多远、隔一道关着的门剩多远，并注明楼上楼下要绕楼梯。

## 3.10 声纹（玩家听觉的呈现）

- **常态也显示。** 阈值本身已经是过滤器：初始阈值 8 只有 20m 内的动静过得来。
  屏息的价值是「把范围再拉开 2m + 自己完全不发声」，而不是「才能看见」。
- **只显示丧尸发出的声音**（脚步、低吼、巡逻动静）。自己扔的石头、开的门不显示 ——
  你知道自己干了什么，不需要 UI 告诉你。
- **形式：挂在声源头顶的世界坐标标记，穿墙可见。** 不是屏幕中心的方向指示环。
  做法是把声源世界坐标投影到屏幕再画图标；声源跑到画面外时收到屏幕边缘，
  变成一个指向它的三角。
- **图标矢量绘制**（脚印 / 声波弧 / 爆点 / 门），不用文字标签 —— 文字在小尺寸下认不出来。
  新响起的标记带一圈外扩涟漪。
- **明显度随 margin 变化：** 强度 = `clamp(margin / 26, 0, 1)`，决定标记半径（8→16px）、
  不透明度与描边粗细。贴脸的动静又大又亮，勉强够到阈值的只是一个淡淡的小点。

**⚠ 待决策：** 现在等级只影响**范围**，不影响**精度** —— 标记直接给精确位置，
等于白送了 10.2 里听觉 Lv5 的「近乎精确定位」。
建议改为：Lv1–3 只给方向（屏幕边缘三角）、Lv4 起头顶显示、Lv5 才去掉位置误差。

## 4.1 时间

| 项 | 值 |
|---|---|
| 1 游戏小时 | 85 秒真实 `[占位]` |
| 白天 | 07:00–19:00（17 分钟） |
| 夜晚 | 19:00–07:00（17 分钟） |
| 完整昼夜 | 34 分钟 |

**夜间声音系数**从 19:00 起在 30 游戏分钟内平滑降至 0.7，05:30 起平滑回到 1.0。
**光照**同样平滑过渡。19:00 后室内没有光源则接近全黑，必须用手电。

> **调优提示：** 17 分钟的白天对整个校园地图偏紧。第一幕（只在宿舍楼）刚刚好，
> 第二幕可能让玩家频繁陷入「来不及回家」的焦虑。备选值 20 或 22 分钟。
> **这个参数必须放在配置文件里。**

## 4.2 夜行

**收益：** 多出一整个 17 分钟窗口 · 丧尸视觉半径减半（听觉不变）· 部分丧尸夜间回到
固定聚集点，某些区域反而空旷。

**代价：** 声音传播距离 +43% · 必须用手电且手电让丧尸视觉半径 ×1.8 ·
放弃精力充沛 buff · 整夜未睡则次日困乏接近满值、几乎无法奔跑。

**这是一个明确的借贷：今晚多干一轮活，明天付利息。**

## 4.3 天气

30 天中安排 6 个雨天：**第 9、13、17、22、25、28 天。天气必须固定，不随机** ——
玩家应该能提前规划。

雨天：雨声掩盖脚步（全局玩家响度 −30%），**是最适合行动的日子**；但视野降低，
丧尸也更难被听见；是唯一的雨水收集窗口。

# 第五部分 · 玩家

## 5.1 移动与姿态

| 姿态 | 速度 | 基础响度 |
|---|---|---|
| 站立行走 | 2.4 m/s | 20 |
| 奔跑 | 4.6 m/s | 45 |
| 蹲行 | 1.2 m/s | 10 |
| 贴墙移动 | 1.0 m/s | 14 |
| 屏息移动 | 蹲行 × 0.5 | 0 |
| 静止 | 0 | 0 |

```
最终响度 = 基础响度 × (1 − 静步减免) × (1 + 0.5 × 负重比)
```

`[实测]` **移动向量只在长度超过 1 时归一化。** 键盘斜向走（长度 √2）被压回 1，
而手柄/摇杆的模拟量（0~1）得以保留 —— 直接无条件归一化会让模拟量输入失效。

## 5.2 潜行动作

**贴墙（单击切换，不是按住）**
- 靠近墙面按键进入，**背贴墙面，朝向沿墙走向**，视角切第三人称，仍可投掷。
- `[实测]` **朝向必须沿墙，不能朝墙外。** 走廊只有 2.6m 深，朝墙外等于脸贴 2 米外的
  另一面墙，第三人称什么也看不见。掩体系统的通行做法就是「背贴墙、视线沿墙」。
- `[实测]` **只有离开进入时那面墙才自动解除。** 走廊里任何位置都离某面墙不到 1.35m，
  只判「附近有没有墙」的话永远解除不了。
- 第三人称相机放在身后并往开阔侧推、抬高。**相机朝向必须与第一人称完全一致**
  （只是位置退到身后）—— 用 `lookAt` 盯身前一点会让光轴与投掷方向越岔越开，准星对不上落点。

**探头（侧身）**
- 站立/蹲下/贴墙时都可以左右侧身。侧身时移动速度为 0（贴墙时仍可沿墙挪）。
- 身体倾约 30°，但**第一人称里唯一看得见的线索是画面翻滚，翻滚只给一半（15°）**，再多会晕。
- `[实测]` **必须加 0.12 秒平滑过渡。违和感的主要来源是瞬间切换，不是角度大小。**
- `[实测]` 平滑之后「侧到一半」成为有效状态：**探出去多少就暴露多少** ——
  被发现半径在 1.0 与 0.35 之间按侧身量插值。
- `[实测]` **侧身时眼位跟着横向探出去**，投掷起点、听觉位置、被发现判定
  全部按探出后的头部位置算。所以「贴掩体侧头扔石头」是成立的动作，代价也如实生效。

**屏息**
- 自身响度降为 0；听觉阈值在当前等级值上 −4；开启声纹显示；消耗体力 3/秒。
- 移动速度限制为蹲行的 50%（**允许缓慢移动** —— 完全禁止会让侦查变成「停下来读地图」，破坏节奏）。

## 5.3 交互

| 动作 | 操作 | 时长 | 响度 |
|---|---|---|---|
| 开/关门窗（快速） | 轻点 F | 瞬间 | 35 / 12 |
| 开/关门窗（缓慢） | 按住 F | 2.5s / 2.0s | 12 |
| **翻找容器** | **F** | **4~7s，按容器大小** | **40** |
| **整个拎走背包类容器** | **按住 F 1.2s** | **1.2s** | **18** |
| 拾取地上的东西 | F | 瞬间 | — |

`[实测]` **翻找只有「快速」一种。** v1 给了快速(4s/40) 与缓慢(9s/15) 两档，
实测下来缓慢那一档**从来没人用**：站在柜子前不动 9 秒的风险，
远大于响度 40 传出去的风险 —— 何况**翻找期间玩家既聋又瞎**，
时长本身就是这个动作唯一真正的代价。留一个没人用的选项只是在教程里多占一行字。

`[实测]` **背包类容器（书包）可以按住整个拎走。** 这是唯一「不用翻」的搜刮方式，
所以它明显更安静（18 对 40）。两种结果，**都不弹取舍窗口** ——
站在柜子前做选择题是最容易送命的时刻：

| 情况 | 结果 |
|---|---|
| 还没有背包 | 直接背上，**里面的东西原样成为背包内容**；原地的书包消失 |
| 已经有背包 | 里面的东西一件件自动塞进现有背包，塞不下的留在原地；书包本身不动 |

第一种是开局最强的一个瞬间：找到第一个书包 = 同时拿到容量和一批物资。
第二种等于「一键全拿」，代价是你得先站在那儿 1.2 秒。

## 5.4 投掷

| 物品 | 落点响度 | 特殊 |
|---|---|---|
| 石头 | 45 | 校园内随处拾取 |
| 玻璃瓶 | 75 | 碎裂，吸引范围大 |
| 发令枪 | 110 | 一次性，结局二布置阶段的关键道具 |
| 闹钟（可制作） | 60，持续 15 秒 | **定时触发，唯一能做到「延迟引怪」的道具** |

**闹钟是潜行深度的关键。** 它让玩家可以规划：提前在 A 点放一个 90 秒后响的闹钟，
自己去 B 点等待。

**投掷预览（必须做）：** 按住蓄力时显示弹道点阵 + 落点标记 + **引怪半径圈**。
半径 = `(落地响度 − 丧尸阈值) / k`，直接告诉玩家「这一下会惊动多大范围」（支柱三）。
UI 上同时给出落点所在节点名与半径数值，并注明**圆圈只是同一空间内的上界，隔墙隔门会更短**。

`[实测]` 两个必须遵守的实现细节：
1. **预览与实弹必须共用同一个定步长积分器。** 预览用固定步长、实弹用逐帧变长 dt 的话，
   两条轨迹根本不是同一条，玩家看到的抛物线和石头真正落的地方对不上。
2. **落点必须取「接触点」，不能取穿透之后的位置。** 石头落在四楼地板上时，
   穿透点在楼板下方，会被判成从三楼发出 —— **在自己脚边扔一块石头会去惊动楼下的丧尸。**
   用二分法求出最后一个未接触的点。

`[实测]` **出手点在右手，不是眼睛正中。** 从眼睛正中抛出去的弧线在屏幕上左右对称，
看着像「从脑门射出来」；挪到右肩下方（右 0.30m、下 0.22m、前 0.18m）之后，
弧线是斜着从画面右下角甩出去的，才像人在扔东西。
**预览与实弹必须共用同一个出手点函数** —— 起点差一点，落点就差一截，
而落点是这个动作唯一的产出。

`[实测]` 预览的点阵开了 `sizeAttenuation`，出手点挪近之后，头几个点离相机只有几十厘米，
会被放大成糊住半个屏幕的黄方块。**跳过 1.0m 以内的点** —— 那几个点本来就在自己身上。

`[实测]` **落地必须有看得见的反馈。** 用户反馈「砸到东西没有产生声音，也没有吸引丧尸」，
查下来**规则层一直是对的**：声音发了（响度 45），丧尸也确实被引过来了。
缺的是画面上的确认 —— 声纹只显示丧尸发出的声音（`soundprintZombiesOnly`），
刚好把玩家自己的石头滤掉，于是蓄力时预览承诺了「落点在哪、引怪半径多大」，
松手之后却什么都没有。

补法：落地时广播 `ProjectileLandedEvent{pos, loudness, radius}`，
界面层在落点画一圈扩散的环 + 引怪半径读数，1.6 秒淡出；
落地音效也从 0.22s 短噪声改成 0.34s 的钝响。
**这条的教训比这个功能本身重要：一个只有听觉反馈的机制，玩家会当成它没生效。**

## 5.5 视觉与被发现

- 感知锥角 110°，半径 14m（白天）/ 7m（夜间）/ 12.6m（夜间持灯）
- 蹲下 ×0.6，探头 ×0.35（按侧身量插值）
- 有遮挡则完全看不见（射线检测，每只丧尸每 0.2 秒一次，只对半径内的丧尸执行）
- 进入视野不是立即发现，有 **0.8 秒识别条**，期间玩家可以退回掩体

## 5.6 跳跃与情境翻越（文档外新增，待拍板）

**⚠ v1 没有跳跃。** 主文档 4.1 的姿态表只有走/跑/蹲/贴墙/静止。以下是应需求新增的。

一个键两种行为：**正前方有可翻越的边缘就翻越，没有才起跳。**

翻越判定：沿正前方每 0.2m 采样，找第一个「顶面高出脚下 0.30–1.45m、
且上方有 0.95m 净空」的位置。0.95m 是按蹲姿通过算的，正好能钻过 1.0m 高的窗洞。

| 情形 | 结果 |
|---|---|
| 床铺（0.55m）、书桌（0.75m） | 翻上去 |
| 打开的窗（窗台 1.0m，窗洞净空 1.0m） | 翻出去 |
| 关着的窗 | 翻不了（窗扇是实体，挡人也挡声） |
| 3.2m 的墙 | 翻不了，退化为原地起跳 |
| 0.2m 的台阶 | 低于阈值，本来走上去就行，不触发 |

| 数值 | 值 | 来源 |
|---|---|---|
| 攀爬/翻窗体力消耗 | −12 / 次 | **文档内**（主文档 3.3） |
| 翻越响度 | 30 | **文档内**（翻窗，声音规格 6.1） |
| 重力 | 18.0 | `[占位]` 文档外 |
| 起跳初速 | 4.2（跳起约 0.49m） | `[占位]` 文档外 |
| 跳跃体力消耗 | 6 | `[占位]` 文档外，取攀爬的一半 |
| 落地响度 | 35 | `[占位]` 文档外 |
| 空中转向能力 | ×0.65 | `[占位]` |
| 郊狼时间 | 0.12s | `[占位]` |

`[实测]` **玩家的水平与垂直运动必须拆开处理。** 加了跳跃之后不能再每帧把角色硬吸附到
地面，需要独立的重力积分、天花板阻挡、走下边沿转入下落。丧尸不跳，仍走吸附式移动。

# 第六部分 · 生存需求

## 6.1 生命条与挤占机制

**生命条总长 100，长度固定不变。** 饥饿与口渴各自在右端生成挤占区：

```
[========= 可用生命 =========][== 饥饿 ==][= 口渴 =]
```

| 规则 | 说明 |
|---|---|
| `可用生命上限 = 100 − 饥饿挤占 − 口渴挤占` | |
| 当前生命不能超过可用上限 | 挤占增长会**压低**当前生命 —— 这就是饿死渴死的机制 |
| 可用上限降至 0 | 死亡 |
| 进食/饮水**立即**减少挤占，上限立即恢复 | |
| **但当前生命不会因此回血** | 挤占解除只是解锁了上限，受过的伤要单独治 |

| 需求 | 0 涨满 100 | 折算 | 每游戏日要补 | 说明 |
|---|---|---|---|---|
| 口渴 | **28** 游戏小时 | 约 2.3 天 | **84 点** ≈ 3.5 份饮水 | 单独不管必死 |
| 饥饿 | **50** 游戏小时 | 约 2 天 | **48 点** ≈ 2 顿正餐 + 1~2 次加餐 | |

两者相加超过 100 时取 100（死亡）。

`[实测]` **这两个数是烹饪系统的前提，改小它们是强制的（见 16.0）。**
v1 的饥饿 96 小时意味着每天只需补 25 点，而一碗白米饭就有 22 ——
**食物完全不构成压力，整套烹饪系统失去存在理由。**

**恢复量：**

| 物品 | 减少口渴 | 减少饥饿 | 备注 |
|---|---|---|---|
| 瓶装水 500ml | 25 | 0 | |
| 煮沸的水 | 22 | 0 | |
| 未处理的水 | 25 | 0 | **40% 概率获得腹泻** |
| 饼干/面包 | 3 | 12 | |
| 泡面（干吃） | −5 | 15 | 加重口渴 |
| 泡面（泡开） | 8 | 25 | 需要热水 |
| 烹饪食物（基础） | 5 | 35 | |
| 烹饪食物（熟练度 5） | 8 | 50 | |

**腹泻：** 口渴增速 ×2，持续 8 小时。自愈或药物。

## 6.2 体力条与困乏

**体力条总长 100，由困乏从右端挤占。** `可用体力上限 = 100 − 困乏挤占`

- 困乏清醒时 **+5 / 游戏小时**（20 小时挤满），睡眠时 **−12 / 游戏小时**
- 因此每天必须睡约 7–8 小时

| 行为 | 体力 |
|---|---|
| 奔跑 | −8 / 秒 |
| 屏息 | −3 / 秒 |
| 攀爬/翻窗 | −12 / 次 |
| 近战挥击 | −6 / 次 |
| 站立不动 | +6 / 秒 |
| 蹲下不动 | +9 / 秒 |

体力归零：无法奔跑，移动速度 −30%，**并产生响度 25 的喘息声** ——
体力耗尽在潜行时是致命的。

## 6.3 睡眠

**安全睡点三个条件缺一不可：**
1. 所在房间的所有 Portal 处于 `Closed` 或 `Blocked`
2. 房间内**及相邻节点**没有丧尸
3. 有床或睡袋

`[实测]` **判定必须逐条给出失败原因并显示给玩家**（「还有门窗没关上」「隔壁有丧尸」
「附近没有床」），否则玩家只会看到「睡不了」而不知道要做什么。

**睡眠过程：** 选择时长（最多 10 小时）→ 时间加速推进 → 饥饿口渴**正常累积** →
若有 `margin > 15` 的响度到达玩家节点，**睡眠中断，惊醒，且不获得当次睡眠的任何 buff**。
中断后可以重新入睡。

**精力充沛 buff：** 22:00 之前入睡且连续睡眠 ≥ 6 小时未被中断 →
次日 24 小时内困乏增速 −25%、体力回复 +15%。

**这个 buff 是玩家规划一天的主要动机 —— 它把「天黑前回家」变成了有正反馈的行为。**

# 第七部分 · 丧尸

## 7.1 总体

- **全校丧尸总数约 320 只，固定，不刷新。**
- 每只有唯一 ID 和持久状态（位置、健康、当前行为），死亡永久移除。
- 未加载区域的丧尸以简化形式模拟（只维护「所属节点 + 目标节点」），玩家进入时还原。

## 7.2 类型（只有三种，不要增加）

| | 游荡者 (85%) | 蜷伏者 (10%) | 奔行者 (5%) |
|---|---|---|---|
| 生命 | 100 | 100 | 60 |
| 游荡速度 | 1.0 m/s | — | 1.2 m/s |
| 追击速度 | 3.2 m/s | 同游荡者 | **5.4 m/s** |
| 听觉阈值 | 10 | 6 | 6 |
| 视觉半径 | 14m | 14m（起身后） | 18m |
| 出现时机 | 全程 | 全程 | **第 12 天后** |

**蜷伏者：** 静止趴伏在暗处、课桌下、床下、储物柜内，远看像尸体。
**只有当声源在 8 米内才起身。** 作用是让玩家不敢放松地穿过看似安全的房间。
屏息时能听到它极轻微的呼吸声（响度 12 的持续 `Ambient` 事件）。

**奔行者：** 比玩家快，**不能靠跑摆脱，只能靠拐角断视线或提前避开**。
第 12 天前完全不出现，作为难度递进的标志。

`[实测]` **头部命中伤害 ×4。** 调查状态的移动速度 = 游荡速度 × 1.6 `[占位]`
（文档只定义了游荡与追击两档，中间态缺失）。

`[实测]` **速度从 v1 的 1.0 / 3.2 下调为 0.65 / 2.9**（奔行者 1.2 / 5.4 → 1.0 / 5.0）。
两个值的理由不同：

- **游荡 1.0 m/s 是「正常人快走」**，看着根本不像拖着腿的东西 ——
  而这是玩家 99% 的时间里看到的样子。压到 0.65（比玩家蹲行 1.2 还慢一半）。
- **追击 3.2 → 2.9**，仍然快过玩家走路 2.4，所以「被发现只能跑」这条没变，
  但留出了「跑两步拉开、拐个弯断视线」的余地，而不是必死。
- **奔行者的 5.0 不能再降**：它是唯一跑得过玩家（4.6）的东西，是第三幕的时钟。

两个值都进了调参面板（P），手感不对可以现场改。

## 7.3 巡逻声（v1 未定义，本版新增）

丧尸有两种常态声，**站着不动的那只也会出声**：

| 声音 | 谁发 | 响度 | 间隔 | 屏息时室内可听 |
|---|---|---|---|---|
| 拖行脚步 | 未趴伏、**正在移动**的 | 48 | 1.1s（奔行者 0.8s） | 23m |
| **低哑嘶吼** | 未趴伏的，**动不动都发** | **28** | 3.0s ±20% | **13m** |
| 喘息 | 奔行者，动不动都发 | 36 | 2.2s ±20% | 17m |
| 呼吸 | 趴伏的蜷伏者 | 12 | 2.5s | 5m |

`[实测]` **常态嘶吼是必须的。** 没有它，一只站着不动的丧尸在声音系统里**等于不存在** ——
实测把全场丧尸钉死不让移动、玩家屏息 20 秒，一只都听不见；加上嘶吼之后
同层 6 只里听见 3 只（另外 3 只在关着门的房间里）。
屏息侦查如果只能发现「正在走动的」，它就只是个移动探测器，不是听觉。

嘶吼定 **28** 而不是 48 有意为之：比脚步近一截，**「站着的比走动的更难发现」**
既符合直觉，也保住了「移动会暴露自己」这条规则。隔一道关着的门只剩 1.5m，
所以它基本只在同一个房间/走廊里起作用 —— 这就是玩家说的「需要稍微更近一点」。

这回答了 v1 第 13.1 节的待定问题 4：**玩家能听见丧尸的常态动静，包括静止时的。**
详见 3.9 的范围表。

`[实测]` **同类之间只有低吼会互相引，脚步、嘶吼与呼吸一概忽略**（它们走 Ambient 类别）。
否则 A 的脚步引来 B，B 一走又发出脚步引来 C，整层楼会自激成一锅粥。
这些声音的存在意义是让玩家听见，不是让丧尸互相听见。

`[实测]` **移动判定必须放在帧末。** 「本帧是否移动了」要拿当前位置和**上一帧末尾**
的快照比 —— 放在帧首比的话两者永远相等，脚步声一次都发不出来。

## 7.4 行为状态机

```
游荡 ──听到声音──> 警觉(转向,延迟) ──延迟结束──> 调查(走向目标点)
                                                  │
调查 ──到达目标点──> 搜索(原地徘徊 8~15 秒) ──超时──> 返回游荡
                                                  │
任意状态 ──看见玩家(识别条满)──> 追击 ──失去目标 6 秒──> 搜索
```

**追击时丧尸持续发出响度 55 的低吼**（每 1.5 秒一次）——
这会引来更多丧尸。**这是本作最危险也最刺激的机制。**

**警觉状态下听觉阈值降到 6**（经修正管线，不写死）。

## 7.5 连锁警戒上限

- 单次连锁最多传播 **2 层**（A 引来 B，B 引来 C，C 不再引人）
- 同时处于追击状态的丧尸全场上限 **12 只**，超过时最远的转为搜索
- **这两个数字必须可配置**

## 7.6 寻路

丧尸在 Portal 图上找路，**只走 `passable` 的连接**（Closed/Blocked 挡人）。

`[实测]` **楼梯必须给四个顺序路点**：走道上对齐梯脚 → 梯脚 → 梯顶 → 上层走道。
只给「梯段中点」的话，丧尸会从走道斜切过去撞在梯段侧面，因为台阶侧壁高度超过
可跨越高度爬不上去。

**⚠ 待决策：丧尸会不会撞门？** v1 未定义。目前关上的门对丧尸是**绝对屏障**，
这让「关门」变成零代价的万能解。响度表里有「撞门 70」，但没有对应的行为规则。

## 7.7 尸群迁移

第 **15、21、26** 天各触发一次（可配置）。全校丧尸的游荡区域重新分配。
迁移当天有明显预兆：清晨大量丧尸同向移动，可以从窗口看到。
**迁移不产生新丧尸，只是重新分布。**

# 第八部分 · 战斗与伤势

## 8.1 武器

**近战为主，武器稀少。第一幕基本没有武器。**

| 武器 | 获取 | 伤害(头/身) | 挥击响度 | 体力 | 耐久 |
|---|---|---|---|---|---|
| 拖把杆 | 宿舍楼 | 25 / 8 | 40 | 5 | 30 |
| 棒球棍 | 体育器材室 | 55 / 20 | 55 | 6 | 80 |
| 消防斧 | 各楼消防箱 | 90 / 40 | 65 | 10 | 60 |
| 钢叉 | 保安室 | 40 / 15 | 50 | 7 | 120 |
| 警棍 | 保安室 | 45 / 18 | 45 | 5 | 150 |
| 菜刀 | 食堂 | 60 / 25 | 35 | 4 | 40 |

**没有枪。** 一所中国学校不该有枪。发令枪是纯噪音道具，不造成伤害。
**这个限制是设计上的优势 —— 它保证了游戏永远不会变成射击游戏。**

## 8.2 战斗规则

- 攻击有前摇（0.4–0.9 秒，依武器），**期间不能取消**
- **背后偷袭：对未察觉的丧尸从背后攻击必定处决**，响度只有 30，不消耗耐久
- **处决是玩家清理丧尸的主要手段。正面战斗几乎总是错误选择**
- 正面被抓 → 挣脱 QTE，失败则被咬；同时被 2 只以上接触 → 必然被咬

## 8.3 伤势

**死亡不应该是瞬间的。玩家应该有机会犯错并挽回，但要付出代价。**

| 伤势 | 来源 | 效果 | 治疗 |
|---|---|---|---|
| 出血 | 被抓、被咬 | 每秒 −0.8 生命，持续至处理 | 绷带 |
| 骨折 | 高处跌落、被扑倒 | 移动 −40%，奔跑时每秒产生响度 50 的痛呼 | 夹板 + 静养 12 小时，或医务室幸存者 |
| 感染 | 被咬，**60% 概率** | 潜伏 6 小时后每小时生命上限 −3，累积至死 | **抗生素**（全校 4 支），或医务室幸存者 + 酒精（60%） |
| 腹泻 | 喝未处理的水 | 口渴增速 ×2，持续 8 小时 | 自愈或药物 |

**抗生素只有 4 支，而感染概率是 60% —— 玩家最多能承受约 6 次被咬。
这个数字定义了整局游戏的容错额度。**

## 8.4 死亡

生命值归零 → 死亡 → 存档删除 → 返回主菜单。无复活、无检查点。

**幸存者笔记（跨局继承，建议实装并默认开启）：** 死亡后，本局已探索过的地图区域、
已发现的配方、已见过的丧尸类型留在一本笔记里，新一局可查阅。
**不提供任何数值优势**，只是省去重复摸索。

理由：一局 10 小时以上的永久死亡，如果每次都要从零重新摸清地图布局，
大部分玩家在第二次死亡后会退坑。**地图知识本来就是「玩家脑子里的东西」，
把它写下来不改变难度，只是减少重复劳动。** 可做成开关，硬核玩家可关掉。

# 第九部分 · 熟练度

六项技能，各 1–5 级。**使用中成长，但只有有意义的使用才计入。**

## 9.1 反刷分设计（重要）

不要按「行为次数」给经验，按**有效行为**给：

| 技能 | 计经验的条件 |
|---|---|
| 静步 | 只有在**某只丧尸的听觉范围内**成功移动而未被察觉才计。原地蹲着绕圈不给 |
| 听觉 | 只有屏息状态下，声纹指向了一个**之前未知的丧尸**才计 |
| 体能 | 只在体力降至 30% 以下时的行动计 |
| 敏捷 | 只在被追击状态下的翻越、冲刺计 |
| 烹饪 | 首次做某配方 **+100**，重复 40/15/5/**0**；黄金窗口 +15；首次用新锅/新热源各 +50。**练不满 5 级除非出门找新配方、新锅、新热源**（见 16.6）|
| 手艺 | 同烹饪，按配方计 |

## 9.2 等级效果

| 技能 | Lv1 | Lv2 | Lv3 | Lv4 | Lv5 |
|---|---|---|---|---|---|
| **静步** | 响度 −8% | −16% | −24%，解锁「极慢步」(0.6m/s，响度 4) | −32% | −40%，蹲行不再触发地面杂物声 |
| **听觉** | **阈值 8→6.8** | 6.8→5.6，声纹显示丧尸类型 | 5.6→4.4 | 4.4→3.2，声纹穿透一层 Portal | 3.2→2.0，近乎精确定位 |
| **体能** | 体力上限 +10 | +20，奔跑消耗 −10% | +30，困乏增速 −10% | +40，消耗 −20% | +50，体力耗尽不再喘息 |
| **敏捷** | 奔跑 +5% | +10%，翻越更快 | +15%，解锁攀爬管道 | +20% | +25%，跌落不再骨折 |
| **烹饪** | 饱腹 +8% | +16%，**黄金窗口 ×1.5** | +24%，腐败 ×0.8 | +32%，烹饪时间 ×0.85 | +40%，**吃变质食物不生病** |
| **手艺** | 搜刮速度 +15% | +30%，解锁闹钟 | +45%，解锁修理 | +60%，封锁更快更安静 | +75%，武器耐久消耗减半 |

**⚠ v1 修订：听觉一列改为阈值（= 可听范围），不再是「方向误差百分比」。**
原因见 3.9。方向精度的分级归入 3.10 的待决策项。

**所有效果通过数值修正管线生效。技能等级不写进任何业务逻辑，业务逻辑只向管线要最终值。**

## 10.1 背包与容器

**格子背包。玩家背包和地上的书包在规则上是同一个东西 —— 同一个 `Grid` 类。**

| 容器 | 尺寸 | 获取 |
|---|---|---|
| （无背包） | — | **开局状态。** 只有 6 格快取栏 |
| 小书包 | 5×4 = 20 格 | 宿舍衣柜里常见，第一个目标 |
| 学生书包 | 5×4 = 20 格 | 宿舍楼/教学楼常见 |
| 战术背包 | 6×5 = 30 格 | 保安室，唯一 |
| 登山包 | 6×6 = 36 格 | 体育器材室，唯一 |

**六格快取栏**：始终可用，不依赖背包，数字键 1–6 直接使用。
**开局没有背包** —— 找到第一个小书包是第一幕的第一个真正目标。

### 格子规则

- 每件物品占 w×h 格，**放不下时自动尝试旋转 90°**
- 可堆叠物品（石头 8、绷带 3、布 5、电池 4、闹钟零件 3）先并进已有的堆
- **「放不下」必须分两种情况提示**（这是可用性问题，不是文案问题）：

| 情况 | 判据 | 提示 |
|---|---|---|
| **背包已满** | 空格总数 < 物品所需格数 | 「背包已满（还剩 N 格，X 需要 M 格）」 |
| **请整理背包** | 空格够，但拼不出连续区域 | 「请整理背包（还剩 N 格，但拼不出 X 需要的连续区域）」 |

**整理**按钮按体积从大到小重排，把碎片挤掉。

### 负重

**负重独立于格子。基础上限 20kg，背包自重计入。**

```
负重比 r = 当前重量 / 上限
脚步响度 × (1 + 0.5r)      体力消耗 × (1 + 0.8r)      奔跑速度 × (1 − 0.25r)
```

超过上限 100% 时无法奔跑。**背得多就吵、就累、就慢** —— 支柱一在物资系统上的体现。

## 10.1c 搜刮

**两种取物方式：**

1. **地上散落的物品** —— 走近按 F 直接进背包，自动排列。
2. **容器** —— 走近按 F 打开，**物品一件一件点亮**（三角洲式），点亮一件才能点它拿走。

| 翻找方式 | 操作 | 总时长 | 响度 |
|---|---|---|---|
| 快速 | 轻点 F | 容器基准时长 | **40** |
| 缓慢 | 按住 F | 基准 × 2.25 | **15** |

**逐个点亮不是装饰：它把「搜刮」变成一段有长度的、可以被打断的过程。**
你在翻箱子的时候是聋的也是瞎的，而箱子越大翻得越久。

**打开背包时游戏不暂停。** 搜刮和整理背包本身就是有风险的行为。

## 10.3 水系统（第二幕的核心矛盾）

- 第 1–7 天：水龙头可用，无限接水（每次响度 30，需要容器）
- **第 8 天 00:00 自来水停供**，所有水龙头失效
- 此后水源：
  1. **瓶装水** —— 有限，总量约够 6 天
  2. **雨水收集** —— 需制作收集器（容器 + 塑料布），放露天处，**下雨天才有产出**
  3. **可疑水源** —— 消防水箱、水池、马桶水箱。未处理直接喝 40% 腹泻，煮沸后安全
  4. **煮沸** —— 电水壶 0.15 小时 / 锅烧 0.40 小时（见 16.8）

**第 11 天 00:00 市电永久失效**（见 15.2）。停水在停电前三天，这个顺序是故意的：
玩家先被迫解决水、习惯了「烧水要用电」，**然后电才被抽走**。

# 第十一部分 · 幸存者

## 11.1 设计约束

**不做跟随 AI，不做战斗 AI，不做寻路跟随。幸存者是固定在位置上的 NPC。**
这是为了让这个系统在单人开发的预算内可实现。

## 11.2 四名幸存者

| 代号 | 位置 | 需求 | 招募后提供 |
|---|---|---|---|
| 老周（保安） | 保安室内间（反锁） | 抗生素 ×1 + 食物 ×3 | 夜间据点警戒：睡眠不再被 margin<30 的声音中断 |
| 小林（学生） | 图书馆书库夹层 | 水 ×4 + 证明外面安全 | 协助搬运：负重上限 +8kg |
| 陈老师（物理） | 实验楼准备室 | 食物 ×2 + 手电 ×1 | 解锁「修理」配方，发电机故障率降低 |
| 医务室的人 | 医务室（藏在药柜后） | 只需找到并说话 | 可治疗骨折、加速感染治疗 |

## 11.3 招募流程

**发现**（环境线索）→ **接触**（对话说明需求）→ **满足需求** →
**迁移**（自行前往据点，过场处理，不做实际寻路，此后固定在据点某位置）

## 11.4 与结局的关系

结局二需要 ≥3 名 · 结局一中幸存者参与最后三夜守城（被他们守住的入口不会被突破）·
结局三（车辆）可带走所有已招募幸存者，**徒步逃离不能带走任何人** ——
这是它成为「最差结局」的原因。

# 第十二部分 · 目标与结局

三个结局互斥，一局只能达成一个。

| | 一 · 等待救援 | 二 · 净化 | 三 · 逃离 |
|---|---|---|---|
| 最早完成 | 第 30 天 | 约第 22 天 | 约第 9 天 |
| 难度 | 中 | 高（真结局） | 低–中 |
| 核心考验 | 资源可持续 + 最终守城 | 探索完整度 + 系统性准备 | 机械修复 + 一次成功突围 |
| 需要幸存者 | 否 | 是（≥3） | 否 |

## 12.1 结局一 · 等待救援

**触发：** 存活至第 30 天 07:00

- 第 1 天起可在多处找到收音机零件。**没有收音机就不会触发第 27 天事件**，
  玩家会莫名其妙地在第 30 天什么也没发生 —— 所以收音机应该在第一幕就被强引导
  （宿舍楼内有一台坏的，零件散落在校内）。
- 第 27 天 08:00 收到军方广播：直升机第 30 天 07:00 抵达，要求**启动并维持定位信标**。
- 信标位于**行政楼天台**。启动需要：发电机 + 柴油 ×2 + 信标装置。
- **信标一旦启动持续发出响度 90 的噪音，不能关闭。** 全校剩余丧尸开始向该建筑汇聚。
- 玩家必须在该建筑内**坚守三个夜晚**（27、28、29 夜）。
- 第 30 天 07:00 直升机抵达。

**设计意图：** 把「活满三十天」从数日子变成一场有明确高潮的攻防战。
玩家前 26 天所有的准备在这三夜集中兑现。

## 12.2 结局二 · 净化（真结局）

**前置条件（全部必须完成）：**
1. **封锁全部 6 个出入口**（正门、后门、东侧门、围墙破口 ×3）。
   每个需建材 ×N + 现场作业 90 秒（期间持续响度 55）
2. **招募 ≥3 名幸存者**
3. **修复广播系统**：广播室钥匙 + 发电机 + 柴油 ×3 + 广播设备零件 ×2 + 手艺 ≥3
4. **改造操场**：4 处可关闭闸口 + 打通一条从广播室到操场的引导路线（沿途门必须 Open）

**执行：** 广播室开启广播（响度 150，覆盖全校）→ 全校丧尸向广播室移动 →
**玩家必须在丧尸抵达前撤离，沿引导路线跑到操场** → 幸存者在玩家通过后依次关闭闸口 →
全部丧尸进入操场后关闭最后一道闸口。

**这是一段约 4 分钟的追逐段落。** 这是唯一一个把整局所有系统都用上的段落。
它应该很难，并且值得。

**执行前必须给玩家明确警告并允许取消。这不是一个可以试错的操作。**
**风险缓解：** 考虑允许「演习模式」（不开广播，仅测试路线跑通时间）。

## 12.3 结局三 · 逃离

- **3a 车辆逃离（较好）：** 车棚有报废电动摩托、校车。修复需零件 ×3 + 电瓶/柴油 +
  手艺 ≥2。修好后从正门驶出（正门必须未被封锁）。
- **3b 徒步逃离（最差）：** 从任一围墙破口离开。不需要任何物品，但破口周边有密集丧尸群。

**设计意图：** 这是「随时可以放弃」的出口，应该始终可用，让玩家在绝望时有选择。
片尾会明确告知玩家放弃了什么（例如「你没能带走任何人」），但**不做道德说教**。

## 13.4 场景加载

- 室外校园：一个常驻场景
- 每栋建筑：独立场景，进入所属室外区域时异步加载，离开一定距离后卸载
- **声音连通图始终全量常驻**（纯数据，几十 KB）
- 未加载建筑内的丧尸以简化形式继续模拟，能正确接收声音并更新目标

`[实测]` 实现要点：

| 参数 | 值 | 理由 |
|---|---|---|
| `loadRadius` | 60 m | 站在主校道上能看到两侧的楼；再远的交给雾 |
| `unloadRadius` | 78 m | **必须大于 loadRadius**，见下 |
| `simplifyRadius` | 60 m | 与 `loadRadius` 同值：看不见的就不必完整模拟 |
| `simplifiedTick` | 0.25 s | 简化模拟的更新间隔 |
| `fogFar` / 丧尸绘制距离 | 60 / 65 m | 绘制距离跟着雾走，两个数分开写迟早会漂 |

1. **进出必须用两个不同的半径（迟滞）。** 只用一个的话，在边界上来回走两步就会
   反复加载卸载，帧率每隔一秒抖一下。**人在楼里就无条件加载**，不管半径怎么算。
2. **「加载」在灰盒阶段只等于「这批盒子出不出现在渲染场景里」。**
   碰撞世界是一张空间哈希，全量常驻反而更省事 —— 卸载它换不来性能，
   只会换来「走进没加载的楼里穿墙」。
3. **声图这个模块根本不碰。** 这是文档的硬规则，也是简化模拟仍然「听得见」的前提。
4. `[实测]` **简化模拟省掉的是视线射线检测和调用频率，不是碰撞的正确性。**
   攒够一个 tick 才动一次，但**攒下来的时间不能一步走完** ——
   奔行者 5.4 m/s × 0.5 s = 2.7 m，一步就跨过 0.2 m 厚的隔墙，
   等玩家走近会发现它站在墙里。必须拆成每步不超过 **0.15 m** 的若干小步
   （`SIM_STEP = 0.15`）。
5. `[实测]` **丧尸必须合批渲染。** 一只一个 `Group`（身体+头+朝向片）= 近千次 draw call，
   实测帧率从 60 掉到 13。合进 3 个 `InstancedMesh`（按实例矩阵写位置/朝向/蹲伏缩放，
   蜷伏者用 `instanceColor` 区分）之后是 3 次；看不见的实例矩阵缩到 0。
   静态几何同理：**按「所属建筑」分组**，组内再按 tag 合批，卸载一栋楼 = 那一组 `visible = false`。

## 13.5 房间节点标注

每个房间/走廊/楼梯间/室外分区挂 `SoundNodeVolume`，
每个门/窗/楼梯口/破洞挂 `SoundPortalLink`，编辑器烘焙工具导出为 `SoundGraph` 资产。

宿舍楼结构规整，**应做成可程序化生成的模板**，只手工放置物资和丧尸。教学楼同理。

`[实测]` **几何体与声音图必须由同一份布局推导出来。** 分成两份手工维护的话，
会出现「声图上有门、几何上是墙」这类几乎无法察觉的 bug。

### 几何构建的三个坑（实测踩过）

1. **楼层节点的 y 边界必须是半开区间**，且要留浮点容差。楼层高度是浮点累加出来的
   （`3 × 3.2 = 9.600000000000001`），闭区间会让站在四楼地板上的点先匹配到三楼节点 ——
   **丧尸低吼、石头落地这类在地板高度发出的声音会被算成从楼下发出。**
2. **楼梯间上方不能盖楼板**，梯段踏板要有厚度但不能从楼板一直填到踏面
   （否则上一层的梯段会占满这一层楼梯的头顶空间，爬到一半顶头），
   梯段上下两端要有落脚平台。
3. **每层楼梯间的梯段区必须留空**，那是从下一层上来的楼梯的洞。
   曾经为了「顶层不再往上」把顶层整个铺平，结果**出生的四楼下不去**。
   正确做法：上下两端的落脚平台每层都有，梯段区永远留空，顶层只是不再生成向上的梯段。
4. **碰撞推出要推到最近的面，不能按移动方向推。** 按移动方向推的话，
   角色一旦陷进一个大盒子（比如顶到楼板），就会被瞬间弹到盒子另一端。

## 14.2b 搜刮界面（与背包总览分开）

`[实测]` **搜刮界面不遮挡游戏画面。** 这是它和背包总览（14.2）唯一但最关键的区别：
翻找时游戏不暂停，玩家必须还能看见身后的走廊 —— 全屏黑底等于把这份紧张感直接抹掉。

布局：**左边是自己的背包，右边是容器**，两块板并排放在画面正中 ——
和「从右边往左边搬」的动作方向一致，中间那条缝就是拖动的路径。
格子板的大小就是它的格子数，5×4 的书包就画成 5×4。

| 操作 | 结果 |
|---|---|
| F（瞄着容器） | 打开，开始翻找并发出响度 40 |
| 再按 F（**朝哪儿看都行**） | 关掉，**不再发一次声音** —— 收界面不是又翻了一遍 |
| Esc / 标题栏「关闭」 | 同上（手机上没有 F 键） |
| 走出交互距离 + 1.6m | 自动关 —— 界面不遮画面，玩家很容易忘了它还开着 |
| 拖动物品 | 容器 ↔ 背包互拖；同一格子板内拖 = 挪位置 |
| 拖动时按 R | 转 90° |

**放不下时依次退让：转 90° → 自动找位置 → 全都不行就原样退回。
东西永远不会凭空消失。**

`[实测]` 三个实现要点：

1. **开关状态归规则层**（容器上的 `searching` 标记），界面层只负责显示。
   界面自己收起时必须回调规则层，否则规则层以为还开着，下一次按 F 会变成「关」。
2. **F 关闭之后要把这一次按键吃掉**，直到松手。否则同一帧的交互判定
   会立刻把容器再打开一次（还会再发一次响度 40）。
3. **鼠标是「借」的，不是「放掉」的。** 只有面板开着的那一会儿解除指针锁定，
   **关掉之后立刻锁回去**，其余时间照常锁定。不锁回去的话玩家得再点一下画面
   才能转视角，而那一下点击还会把开场层顺带招回来，像是游戏断了一下。
   关闭动作本身（按 F、按 Esc、点「关闭」）都带用户手势，所以锁得回去。
   界面开着时点空白处也不能重新抢锁，否则鼠标又没了、格子拖不动。
   三个面板（搜刮 / 笔记本 / 背包）共用装配层的一对方法，**开一次配一次**。
   `[实测]` 笔记本的 `toggle()` 曾经自己写了一遍收起逻辑，绕过 `close()`，
   于是按 J 合上时鼠标没锁回去 —— 合上必须走 `close()`。
4. `[实测]` **解除指针锁定会把「点击画面开始」那层重新弹出来。**
   开场层的显隐原来只看「锁没锁上」，而面板是主动解锁的 ——
   于是一开背包/笔记本/搜刮界面，开场层就糊在面板背后。
   正确条件是「还没开始过，**或者**玩家自己按 Esc 放开了鼠标且没有任何面板开着」。

### 观察页

`丧尸类型 × 怎么知道的（看见 / 听见）` 各记一条，附「第 N 天起」和累计次数。
**这一页的价值在于把玩家自己摸出来的规律固化下来，而不是提前告诉他** ——
所以它记的是「你见过什么」，不是「它们是什么」。

`[实测]` 「看见」的判定：视锥半角 60° + 有视线 + 25m 内，**0.4 秒查一轮**，
射线检测不便宜，全校 320 只每帧全查会把帧时间吃掉一半。
「听见」直接挂在玩家听觉组件的回调链上，不额外算。

ESC 呼出，游戏暂停，可保存并退出。
**不能在暂停菜单里读档。存档只在启动游戏时加载一次。**

## 14.4b 转视角与「开始游戏」

`[实测]` **不能把「游戏开始」挂在指针锁定成功上。**
这个页面经常被嵌在 sandbox 的 iframe 里（artifact、itch.io、各种嵌入页），
少了 `allow-pointer-lock` 权限时 `requestPointerLock()` 会被直接拒绝，
控制台只留一行 `Blocked pointer lock … the element's frame is sandboxed`。
一旦把 `startHint` 的隐藏放在 `pointerlockchange` 里，**玩家点了没反应，游戏根本进不去**。

正确的分层是：**点击 = 开始，锁不锁得上是另一回事。**

| 模式 | 触发 | 转视角方式 | 灵敏度 |
|---|---|---|---|
| `lock` | 指针锁定成功 | 鼠标随便动（`movementX/Y`） | 0.0022 |
| `drag` | 锁定被拒（`pointerlockerror` 或 Promise reject） | **按住左键拖动**（`clientX/Y` 差分） | 0.0040 |
| 触屏 | `pointer:coarse` | 空白处拖拽 | 0.0042 |

拖动模式的行程被窗口宽度限制住，灵敏度要高一些手感才接近。
落到拖动模式时给 `body` 加个 class 换成抓手光标，并弹一次提示 ——
否则玩家不知道要按住左键。**开场层在拖动模式下不能弹回来**
（`pointerlockchange` 里判断的是「本该锁上却没锁上」，不是「没锁上」）。

## 14.5 触屏适配（若做移动端）

- 左下虚拟摇杆输出**模拟量**；空白处拖拽转视角（没有指针锁定）
- 修饰键（蹲/跑/贴墙）做成**开关**，手机上没法「按住 Shift」
- **长按与蓄力的进度画在按钮本身上** —— 手机没有准星旁的提示环
- 渲染分辨率压到 **1.25 倍 DPI**，按 3x DPR 渲染会掉到 20fps 以下，潜行手感全毁

# 第十五部分 · 供电系统

> **第 2 层（规则层）。** 它不知道厨房、不知道信标、不知道玩家 ——
> 它只回答一个问题：**这条链路现在有多少瓦可用，接上这台设备会不会跳。**
> 烹饪（第 4 层）可以向下查询供电；**供电永远不能向上问烹饪**。
> 代码：`src/29-power.js`

## 15.1 为什么要有电

因为**电是这个游戏里唯一一种「安静的能量」**。

篝火有光有烟，燃气有火有响，只有电是无声的 —— 但它有三个代价，正好构成三种玩法：

| 代价 | 逼玩家做什么 |
|---|---|
| **有上限** | 算功率。同时开的东西加起来超了就跳闸 |
| **会断** | 第 11 天市电永久失效，之后每一度电都要自己造 |
| **自己发电会响** | 柴油发电机 65 dB —— 比玩家跑步还响。开机就是在喊「我在这里」 |

**核心张力：市电时期玩家在算功率，停电之后玩家在算噪音。**

## 15.2 两个关键日期

| 天 | 事件 | 后果 |
|---|---|---|
| 第 8 天 00:00 | 自来水停供（见 10.3） | 所有水龙头失效 |
| **第 11 天 00:00** | **市电永久失效** | **不可修复。** 广播为 `PowerLostEvent { reason:'gridFail' }` |

**停电必须是永久的、不可修复的。** 如果玩家能修好市电，整个发电机 / 柴油 / 太阳能的
经济全部作废，第三幕就没有压力了。配电箱可以复位跳闸，**但修不好没电的电网**。

停水在停电前三天。这个顺序是故意的：玩家先被迫解决水，习惯了「烧水要用电」，
**然后电才被抽走** —— 于是第 11 天那一刻，玩家同时失去饮水和烹饪。

## 15.3 电源

| 电源 | 功率 | 燃料 | 消耗 | 响度 | 重量 |
|---|---|---|---|---|---|
| 市电 | **2200 W** | — | — | 0 | — |
| 柴油发电机 | 3000 W | 柴油 | 0.45 L/h | **65** | 28 kg |
| 小型发电机 | 1200 W | 柴油 | 0.20 L/h | **52** | 14 kg |
| 汽车电瓶 | 1000 W | 电量 600 Wh | — | 5 | 16 kg |
| 太阳能板 ×3 | 见下 | — | — | 0 | 7 kg / 块 |

**太阳能单块输出（`[新增]` 平衡值）：**

| 晴天 | 阴天 | 雨天 | **夜间** |
|---|---|---|---|
| 220 W | 110 W | 40 W | **0 W** |

> **夜里是 0，这一点不能忘。** 太阳能是「白天的电」，
> 而玩家最需要电的时候（烧水、做饭、开灯）大多在晚上。
> 三块板晴天满配 660 W —— 够点灯、够电炖锅，**不够电磁炉（2000 W）**。
> 这就是电瓶存在的理由：白天用太阳能充电瓶，晚上用电瓶。

**柴油总量：全校 46 L。** 这个数字是硬约束，因为它直接决定结局二能不能达成：

```
信标 500 W × 72 小时  →  大发电机连续跑 72 h  →  0.45 × 72 = 32.4 L
32.4 / 46 = 70%
```

**结局二要吃掉全校三分之二的柴油。** 玩家在第 27 天启动信标之前的每一次
「今晚开发电机做顿好的吧」，都是在拆自己的结局。这是本作**唯一一处**
让日常舒适度和终局目标直接冲突的设计，必须保留。

## 15.4 电线与插孔

电源和设备之间不是无线连接的。**每一条链路都要用实物电线接出来，长度有限。**

| 电线 | 长度 | 插孔 | 重量 |
|---|---|---|---|
| 短电线 | 3 m | 1 | 0.3 kg |
| 插线板 | 5 m | 4 | 0.6 kg |
| 工程延长线 | 15 m | 2 | 2.4 kg |
| 电缆盘 | **30 m** | 3 | 6.0 kg |

**串联规则：**

```
总长度 = Σ 每段长度
总插孔 = Σ 每段插孔 − (段数 − 1)      ← 每接一段线要占掉上一段的一个孔
```

`[实测]` 这条减法很重要。不写的话，玩家会串八个插线板得到 32 个插孔，
功率上限就变成了唯一约束，**电线本身失去了意义**。

**30 m 电缆盘 vs 发电机 65 dB —— 这是全系统最重要的一对数字。**

```
可听半径 = (65 − 10) / 2.0 = 27.5 m   （室内，丧尸阈值 10）
```

**27.5 m < 30 m。** 也就是说：**用满一整盘电缆，刚好能把发电机放到它自己听不见的地方。**
差值只有 2.5 m —— 玩家必须精确地布线，不能随便一扔。
室外 k = 1.2 时可听半径 45.8 m，一盘线不够，得两段接力。

## 15.5 回路、跳闸与配电箱

**回路（Circuit）是死的。** 一栋楼有若干条回路，每条回路对应一组插座。
市电时期，回路的功率上限就是市电上限；停电后回路只是导线，**上限取决于挂上去的电源**。

| 状态 | 含义 |
|---|---|
| `Off` | 配电箱的闸没推上 |
| `On` | 通电 |
| `Tripped` | **跳闸** —— 瞬时总功率超过上限 |
| `Dead` | 线路损坏，需要「修复回路」（手艺 2） |

**跳闸的三条规则：**

1. **跳闸永远是玩家算错了，不是随机事件。** 所以厨房面板必须把「已用 / 上限」放在最上面。
2. **跳闸会毁掉正在做的东西。** 正在烹饪的锅直接进入 `Ruined`。
3. 跳闸响度 **40**，推闸响度 **25**。跳闸比推闸响 —— 失误的代价包含噪音。

`[实测]` 推闸声 25 在室内的可听半径是 `(25−10)/2.0 = 7.5 m`。
配电间通常在一楼角落，7.5 m 大约是「同一条走廊听得见，隔一道门听不见」。
这个距离让「去推闸」变成一次真正的潜行任务，而不是一次散步。

# 第十六部分 · 烹饪与食材

## 16.0 前置改动：需求速率必须先改

`[实测]` **在改需求速率之前，整套烹饪系统是没有存在理由的。**

v1 的饥饿是 96 小时涨满 100，折算下来每游戏日只需要补 **25 点饥饿** ——
而一碗最简单的白米饭就有 22 点。**一天做一次最低级的饭就够了，
32 个配方、熟练度、黄金窗口、气味，全部是无用功。**

| 需求 | v1 | **v2** | 折算 |
|---|---|---|---|
| 口渴涨满 | 30 h | **28 h** | 每日约 3.5 份饮水 |
| 饥饿涨满 | 96 h | **50 h** | 每日约 2 顿正餐 + 1~2 次加餐 |

**新值下每游戏日需要补：饥饿 48 点 / 口渴 84 点。**
这才让「今天吃什么」成为一个每天都要回答的问题。

## 16.1 一次烹饪需要三样东西

```
        热源  ×  锅具  ×  配方
         ↑       ↑        ↑
       要电   要兼容    要熟练度
```

**三者缺一不可，而且互相约束。** 这个乘法关系是整个系统的骨架：
玩家有电磁炉不一定能做饭（还要有锅），有砂锅不一定能用（电磁炉加热不了砂锅），
有材料不一定会做（熟练度不够）。

### 热源

| 热源 | 瓦 | 待机响度 | 爆炒响度 | 要锅 | 速度 | 自动断电 | 完成提示音 |
|---|---|---|---|---|---|---|---|
| 电磁炉 | 2000 | 18 | **45** | 是 | ×1.00 | 否 | — |
| 电陶炉 | 1500 | 12 | **45** | 是 | ×1.35 | 否 | — |
| 电水壶 | 1500 | 15 | — | 否 | ×0.50 | 是 | **35** |
| 微波炉 | 1200 | 30 | — | 是(饭盒) | ×0.40 | 是 | **50** |
| 电饭煲 | 800 | 10 | — | 否 | ×1.00 | 是 | 22 |
| 电炖锅 | 300 | 8 | — | 否 | ×3.00 | 是 | — |
| 卡式炉 | **0** | 20 | **45** | 是 | ×1.00 | 否 | — |

> **速度是「所需时间的倍率」，不是快慢** —— ×0.40 的微波炉是最快的，×3.00 的电炖锅最慢。

**三条读法：**

1. **微波炉最快但完成提示音 50** —— 那一声「叮」的可听半径是 `(50−10)/2 = 20 m`，
   能穿过大半层楼。**微波炉是「省时间但暴露位置」的选择。**
2. **电炖锅 300 W、待机 8、慢三倍** —— 它是唯一能在太阳能 / 电瓶上安全运行的热源，
   也是唯一能「炖着出门」的。老火靓汤 180 分钟、高汤炖肉 200 分钟只能用它（`slowOnly`）。
3. **卡式炉 0 W** —— 停电后唯一还能爆炒的热源。丁烷 5 罐 × 3 小时 = **15 小时**，用完就没了。

### 锅具

| 锅 | 重 | 标签 | 加成 |
|---|---|---|---|
| 铁炒锅 | 2.2 | fry | 饱腹 ×1.15 |
| 平底锅 | 1.1 | fry | — |
| 不锈钢汤锅 | 1.4 | boil / soup | — |
| **砂锅** | 2.6 | boil / soup | 饱腹 ×1.10、**解渴 ×1.25**，但 **20% 概率摔碎** |
| **高压锅** | 3.1 | boil / pressure | **时间 ×0.40**，但结束要泄压 |
| 蒸锅 | 1.8 | steam | **buff 时长 ×1.5** |
| 奶锅 | 0.6 | boil | 时间 ×0.60，**但只能做半份** |
| 玻璃饭盒 | 0.4 | microwave | 微波炉专用 |

**高压锅泄压是一个二选一：**

| 选择 | 响度 | 代价 |
|---|---|---|
| 等 15 分钟慢慢放 | **20** | 15 分钟，且黄金窗口在流逝 |
| 立刻放 | **55** | 比追击低吼还响 |

**这是全系统最好的一个决策点** —— 它把「快」和「安静」直接对立起来，
而且发生在玩家已经投入了 24 分钟烹饪之后。

### 兼容矩阵（硬规则）

| | 铁炒锅 | 平底锅 | 汤锅 | 砂锅 | 高压锅 | 蒸锅 | 奶锅 | 饭盒 |
|---|---|---|---|---|---|---|---|---|
| 电磁炉 | ✓ | ✓ | ✓ | **✗** | ✓ | ✓ | ✓ | ✗ |
| 电陶炉 | ✓ | ✓ | ✓ | **✓** | ✓ | ✓ | ✓ | ✗ |
| 卡式炉 | ✓ | ✓ | ✓ | **✓** | ✓ | ✓ | ✓ | ✗ |
| 微波炉 | ✗ | ✗ | ✗ | ✗ | ✗ | ✗ | ✗ | **✓** |
| 电水壶 / 电饭煲 / 电炖锅 | 自带内胆，不接锅具 |

**电磁炉加热不了砂锅**（电磁炉靠涡流，砂锅不导磁）。这不是刁难，
这是让「电陶炉」这台功率更低、更慢的设备有存在意义的唯一理由。

## 16.2 黄金窗口

```
开火 ─────── 完成 ───── 黄金窗口 ───── 过火 ───── 报废
  0          T          T+0.20T      T+0.60T    T+1.00T
             └──────────┘
              在这里取出 → 饱腹 ×1.0，+15 熟练度经验
```

| 阶段 | 结果 |
|---|---|
| 未完成 | 取出得到生食 |
| **黄金窗口**（完成后 20% 时长内） | 满值，**+15 经验** |
| 过火（20%~60%） | 饱腹线性衰减至 **×0.40**，气味 +1，响度 +10 |
| 报废（60% 之后） | 饱腹固定 **5**，气味 3，广播 `CookingRuinedEvent` |

**熟练度 2 级后黄金窗口 ×1.5。** 这是熟练度最有体感的一个效果 ——
不是「做得更好」，是「更不容易做砸」。

**自动断电的设备（电饭煲/电水壶/微波炉/电炖锅）不会过火。**
所以它们是「安全但慢」，电磁炉/电陶炉是「快但要盯着」。
**这条区分让「今天用哪台设备」在出门计划里有了意义。**

`[实测]` 阶段推进必须能**一次跨过好几段**。写成 `if / else if` 的话，
玩家炖着汤出门一趟（一次 update 跨了两小时）只会从「烹饪中」走到「黄金窗口」，
**永远不会糊** —— 过火和报废形同虚设。必须用循环走到该停的地方为止。

## 16.3 调味与产出计算

```
饱腹 = 基础
     × (1 + 熟练度加成)              Lv0~5：0 / .08 / .16 / .24 / .32 / .40
     × (1 + 调味槽数 × 0.08)          最多 3 槽 → 最高 ×1.24
     × 锅具加成                       铁炒锅 1.15、砂锅 1.10
     × 新鲜度倍率                     见 16.4
     × 阶段倍率                       黄金 1.0，过火 1.0→0.4
```

**调味料是乘法不是加法。** 加法的话高级配方会被调味料喂饱，
乘法则让调味料「锦上添花」——它放大好菜，也放大烂菜的无用。

**口渴列的符号：负数表示解渴。** `thirst: -36` = 减少 36 点口渴。
汤类是本作最重要的水源之一：老火靓汤 −42、三鲜锅 −36、腐竹木耳汤 −34。
**第 8 天停水之后，「会做汤」直接等于「活得下去」。**

## 16.5 气味

**气味是烹饪独有的代价，而且它绕过了所有隔音。**

```
持续时间 = 气味等级 × 45 游戏分钟
效果     = 该节点及相邻节点的丧尸听觉阈值 −(气味等级 × 2)
```

阈值 −2 意味着可听半径涨 1 m（室内 k=2）。气味 3 级 → 阈值 −6 → **可听半径 +3 m，持续 2.25 小时**。

**做一顿好饭，等于在两个小时里把整层楼的丧尸耳朵调灵敏一档。**
这是「奖励必须有代价」的最直接体现：高级配方饱腹高、解渴多、给 buff，
**气味也一律是 3。**

`[实测]` **气味的数据必须挂在 `SoundGraph`（第 1 层）上，不能走修正管线。**
修正管线（1.3）按 `ownerId` 过滤，而气味是**按节点**生效的 —— 塞不进去。
现在的分工是：烹饪（第 4 层）写入气味，听觉（第 2 层）读取，**两边互不认识**。
关着的门会挡住气味向相邻节点扩散。

## 17.1 核心判断：宿舍楼不能一只丧尸都没有

这是整个教学设计里唯一一个真正的判断，其余全是它的推论。

**如果出生的宿舍楼完全空置，会发生什么：**
玩家会花二十多分钟，熟练地掌握一个**没有威胁的游戏** ——
然后在推开大门的那一刻，被迫在三十秒内同时理解声音传播、潜行姿态、投石引怪、屏息侦查。

> **教学教会了错误的游戏，而真正的考试在门外。**

**但反过来，「开局就有丧尸」又会摧毁「安心入手」。**

**正确的解法是把危险分级：每一个机制都在零风险的环境下被教会，然后才拿到有风险的环境里考。**

## 17.2 危险分层（关卡布置）

| 楼层 | 丧尸 | 状态 | 教什么 |
|---|---|---|---|
| **四楼（出生层）** | **0** | — | 移动、交互、搜刮、背包、需求条 |
| 三楼 | **0** | — | 电力、水、手电 |
| **二楼** | **1** | **锁死在 205 里，永远出不来** | **全部声音机制** |
| 一楼 | 1 | 走廊巡逻，**自由活动** | 第一次真正的考试 |

**玩家在见到第一只可能伤害自己的丧尸之前，有约 15 分钟的完全安全时间。**
「安心入手」完全满足，而且**教学没有骗人** —— 二楼那只是真的丧尸，会吼、会撞门、会被石头引，
它唯一不会做的事是走出那个房间。

`[实测]` 205 那只的实现是 `lockedIn` 标志 + 状态机里一条提前返回的分支：
它照常听、照常进入追击态、**照常以响度 70 撞门**，只是不寻路、不移动。
撞门声 70 在室内的可听半径是 `(70−10)/2 = 30 m` —— **整个二楼都听得见**。
这是玩家第一次体会到「声音会穿过墙，但门会削弱它」。

**省下来的丧尸名额挪到室外，全校总数仍然是 320**（不能因为教学而让全校变松）。

## 17.3 七个目标

**全部用主角的第一人称内心独白语气，不用系统指令语气。**

> ✗「前往一楼配电间推上电闸」
> ✓「水壶插上了没反应。配电间应该在一楼。」

**这不是文风偏好。** 指令语气会把玩家变成执行者；独白语气让玩家觉得那是**他自己想到的**。
这个游戏的支柱三是「玩家应该能在脑内推演」——**推演的前提是玩家相信结论是自己得出的。**

| # | 目标（原文） | 教什么 |
|---|---|---|
| 1 | 嗓子干得厉害，先找点喝的。 | 移动、交互、搜刮、需求条 |
| 2 | 东西拿不下了，得找个包。 | 背包、格子、重量 |
| 3 | 有水壶，烧点开水吧。 | 插座、电线、**回路是死的** |
| 4 | 楼下有声音。 | **全部声音机制** |
| 5 | 天黑了。今晚就在这儿吧。 | 封锁、睡眠、安全睡点 |
| 6 | 配电间在一楼。 | 潜行实战、推闸 |
| 7 | 不能一直待在这栋楼里。 | 投石过开阔地 |

**目标的呈现：左上角一行小字，5 秒后淡出。不做任务列表面板。**
长按 Tab 可以重新调出当前目标。

**目标 3 是整个教学的枢纽。** 玩家找到水壶、插上、**没反应** ——
这个失败是设计好的，它同时教会了「插座」「回路」「配电箱在一楼」三件事，
并且把玩家推向目标 6。**出生的 402 所在回路开关是断开的**，这是关卡布置里最重要的一条。

| T14 | 按键 `Q / E` | 探头 |
| T15 | 按键 `Ctrl` | 蹲行 |
| T16 | 独白 | 天黑了 |
| T17 | 面板「睡不着」 | 门开着，挡不住什么 |
| T18 | 按键 `F` | 封锁 |
| T19 | 面板「睡眠」 | 22:00 前入睡且睡满 6 小时会得到「精力充沛」。睡眠会被声音吵醒 |
| T20 | 面板「通电了」 | 每条链路有功率上限，超了会跳闸，**跳闸会毁掉正在做的东西** |
| T21 | 面板「跳闸」 | 同时开的设备加起来超过了上限。去配电箱复位 |
| T22 | 面板「净化」 | 烧开的水可以放心喝。第 8 天之前自来水是安全的 |

**T09（屏息）是全表最重要的一条。**
如果玩家错过它，整个二楼的教学都会失效 —— 他会带着「看不见丧尸」的印象走进一楼。
所以它的触发条件最宽松，而且是**全表唯一允许重复一次的提示**（8 秒后可再提示一次）。
玩家一旦真的按过 Z，提示就永久收起。

**四种提示形式全部不暂停游戏。** 这个游戏从第一秒起就不给人喘息。

`[实测]` 判断「这条提示出现过没有」必须用 `!== undefined`。
写成 `if (shown[id])` 的话，游戏第 0 秒触发的提示存进去的时间戳是 `0`，
下一次判断时 `0` 是假值 —— **提示会被重复播一遍**。

## 17.7 结束与跳过

**教学结束后，目标 UI 永久消失，整局游戏再也不出现。**

**没有庆祝、没有「教学完成」字样、没有音乐变化。**
这个消失本身就是一句话：**从现在起，没人告诉你该干什么了。**

结束时向笔记本写入一条线索「离开宿舍楼」，广播 `TutorialFinishedEvent`。

**跳过教学：关卡布置不变，只是没人说话。**
205 那只依然锁着，一楼那只依然巡逻，石头依然在男201，纸条依然在桌上。
**老玩家跳过的是提示，不是关卡** —— 因为关卡本身就是好关卡。

| 5 | 开场卡片的规格行是手写的 | 换了地图之后文案还写着「4F × 6 ROOMS」 | 由实际建出来的关卡填 |
| 6 | 笔记本地图在手机横屏被挤出屏幕 | 390px 高的屏幕上标记按钮看不见 | 地图高度改成 `min(320px, 46vh)` + 矮屏专用规则 |
| 7 | 存档没有背包和容器 | 读档后背包空了、翻过的柜子又满了 | 存档升到 v2（见 1.5） |
| 8 | 「开始游戏」挂在指针锁定成功上 | **在 sandbox 的 iframe 里点了没反应，游戏进不去** | 点击即开始，锁不上就退到「按住左键拖动」（见 14.4b） |
| 9 | 右键屏息在拖动模式下弹出浏览器右键菜单 | 屏息一按就断，玩家以为屏息没用 | `contextmenu` 改成「游戏已开始就吃掉」，不再只看 locked |
| 10 | 开局身上一件东西都没有 | **按 G 什么也不发生**，投石这个核心动作在第一分钟就是坏的 | 开局给 4 块石头；且没石头时明确提示，不再静默失败 |
| 11 | 关着的木门衰减 45 vs 丧尸脚步 48 | 关上门=绝对听不见门后，屏息侦查在楼里彻底没用 | 降到 25（见 3.7），同时解决待决策 #2 |
| 12 | 声纹标记只有 8~16px、最低强度 0.35 | 灰盒的浅色墙上几乎看不见，玩家以为屏息没出声纹 | 12~22px、强度下限 0.6、加深色描边打底 |
| 13 | 缓慢翻找从来没人用 | 站在柜子前不动 9 秒的风险远大于响度 40 传出去的风险 | 翻找固定为快速一种（见 5.3） |
| 14 | 走廊只有 2.6m | 第一人称里两侧墙压在脸上，而走廊是待得最久的地方 | 加宽到 3.4m |
| 15 | 丧尸模型肩宽 0.55、高 1.66 | 在窄走廊里像堵墙，两只并排就封死了路 | 肩宽 0.42、高 1.55（成年人肩宽约 0.45） |
| 16 | 丧尸游荡 0.65 m/s 还是偏快 | 玩家第二次反馈「还是太快」 | 降到 0.45（玩家蹲行 1.2 的三分之一），追击 2.9 → 2.7 |
| 17 | 翻找容器要全屏变黑 | 翻找时游戏不暂停，但玩家看不见身后的走廊，紧张感没了 | 改成不遮挡画面的两块格子板（见 14.2b） |
| 18 | 面板解除指针锁定 → 开场层弹回来 | 一开背包/笔记本/搜刮，「点击画面开始」就糊在面板背后 | 显隐条件加上「没有面板开着」（见 14.2b） |
| 19 | 站着不动的丧尸完全静默 | 全场钉死后屏息 20 秒**一只都听不见** —— 屏息只是个移动探测器 | 加常态低哑嘶吼 28（见 7.3） |
| 20 | 碰撞推出会把深陷的角色甩出去 | 实测简化模拟里的游荡者**单帧位移 2.43m**，一步跨过整面墙 | 推出距离超过 0.6m 就放弃这一帧的移动，原地不动 |
| 21 | 面板解锁鼠标后不锁回去 | 关掉容器还得再点一下画面才能转视角，开场层还会顺带弹一次 | 「借鼠标 / 还鼠标」成对，三个面板共用（见 14.2b） |
| 22 | 石头落地只有听觉反馈 | 被当成「没产生声音、没吸引丧尸」，而规则层一直是对的 | 落点画环 + 引怪半径读数（见 5.4） |
| 23 | 投掷出手点在眼睛正中 | 弧线左右对称，像「从脑门射出来」 | 挪到右手；预览与实弹共用同一个出手点 |

`[实测]` 第 1、2 两条是**同一类错误的两面**：M0/M1 里只有 4 只丧尸、一栋楼，
「一只一个对象」「攒着一次走完」都看不出问题。
**规模上去之后才暴露的东西，只能靠先把规模建出来再测。**
这也是 M2 值得单独做一个里程碑的理由。

## B.6 供电 / 烹饪 / 教学 实施中发现并修正的问题

**这一批的第 1 条是「实现暴露了设计缺陷」最典型的一次** ——
它不是代码 bug，是把两份规格接起来之后，算术自己说话了。

| # | 问题 | 后果 | 处理 |
|---|---|---|---|
| 1 | **饥饿 96 小时涨满 = 每天只需补 25 点**，而一碗白米饭 22 点 | **食物完全不构成压力，32 个配方、熟练度、黄金窗口、气味全是无用功** | 口渴 30→28、饥饿 96→**50**（见 6.1 / 16.0）。这是烹饪系统能成立的前提 |
| 2 | v1 的「食堂燃气灶」是免费、无限、无声的热源 | 它一存在，整个供电系统就没有存在意义 | 删除。热源全改为电器，唯一例外是烧丁烷的卡式炉（15 小时用完） |
| 3 | 气味是**按节点**生效的，而修正管线按 `ownerId` 过滤 | 塞不进管线，硬塞就要打破分层 | 气味数据挂到 `SoundGraph`（第 1 层）：烹饪（4 层）写，听觉（2 层）读，两边互不认识 |
| 4 | `canCook` 把设备自己的功率算进了「已用」 | 同一台灶第二次开火会被**自己**挡住，报一个看不懂的「功率不够」 | 算余量时先把自己的瓦数从已用里刨掉 |
| 5 | 阶段推进写成 `if / else if` | 玩家炖着汤出门（一次 update 跨两小时）只会走一格，**过火和报废形同虚设** | 改成循环，一次能跨过好几段 |
| 6 | 提示的「出现过没有」判断写成 `if (shown[id])` | 第 0 秒触发的提示存进去是 `0`，是假值 —— **提示重复播一遍** | 改成 `!== undefined` |
| 7 | 厨房面板的配方材料显示的是 id | 玩家看到的是 `rice + water` | 加 `Config.ingredientNames`，id → 中文 |
| 8 | 功率进度条在上限为 0 时渲染成满格 | 「闸没推」被读成「用满了」，玩家去关设备而不是去推闸 | 上限 ≤ 0 时进度条为空，并显示「这条回路没电」 |
| 9 | 笔记本 `toggle()` 绕过了 `close()` | 按 J 关掉笔记本后鼠标不锁回去 | 统一走「借鼠标 / 还鼠标」那对函数 |

**另外三个数字是刻意对齐的，改任何一个都要重新验算：**

1. **信标 500W × 72h = 32.4 L，全校柴油 46 L** —— 结局二要吃掉 70% 的柴油。
   玩家每一次「今晚开发电机做顿好的」，都在拆自己的结局。
2. **发电机 65 dB → 室内可听半径 27.5 m，电缆盘 30 m** —— 差 2.5 m。
   用满一整盘线刚好能把发电机放到它自己听不见的地方，但必须精确布线。
3. **撞门 70 dB → 可听半径 30 m** —— 二楼 205 那只锁死的丧尸撞门，整层楼都听得见。

## B.4 实现顺序建议

如果从零重做，按这个顺序，每一步都能独立验证：

```
1. 事件总线 + 修正管线 + 确定性随机          （无依赖，纯数据结构）
2. 声音连通图 + Dijkstra 传播 + 听觉组件      （只依赖 1）
3. 游戏时钟 + 夜间系数曲线                    （只依赖 1）
4. 灰盒关卡生成（几何与声图同源）              （只依赖 2）
5. 碰撞/视线/翻越探测                          （只依赖 4）
6. 玩家控制器 + 投掷                           （依赖 2/4/5）
7. 丧尸状态机 + 图上寻路                       （依赖 2/4/5）
8. 需求 + 睡眠 + 存档                          （依赖 3）
9. 渲染 / 音效 / HUD / 调试工具                （只读上面的状态，不反向写）
```

**第 1–8 步不应该引用任何渲染引擎的类型。** 这不是洁癖：
这套规则的每一个数字都要反复调，只有能在 CLI 下秒级跑完全部测试，
调参才不会变成「改一个数、开一次引擎、玩五分钟、发现哪里又坏了」。
