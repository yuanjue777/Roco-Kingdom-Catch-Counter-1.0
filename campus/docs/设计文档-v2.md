# 第零部分 · 给实现者的说明

## 0.1 怎么用这份文档

**新开一个对话时，先贴第零部分和第一部分（架构），那是硬约束；然后说「实现 X 系统」。**

每个系统章节的结构是固定的：**规则 → 数值表 → 已知结论 → 待决策**。
「已知结论」是实测得出的、文档 v1 里没有的事实；「待决策」是还需要人拍板的地方。

## 0.2 硬性约束（任何时候不能违反）

1. **分层依赖单向。** 下层不得知道上层的存在、不得引用上层类型。分层见 1.1。
2. **系统之间不直接调用，通过事件总线通信。** 唯一例外是向下查询（上层可读下层的只读接口）。
3. **任何游戏数值在使用前必须经过数值修正管线。** 不要在业务代码里写死数字。
4. **所有运行时状态必须可序列化。** 存档是随时保存，不是检查点保存。
5. **不要发明文档里没有的机制。** 有疑问就留 TODO 并报告，不要自行补全。
6. **每个数字都要能回答「这个数是怎么来的」。** 本文档中标注：
   `[实测]` 已在原型上验证 · `[推导]` 由其他数值算出 · `[占位]` 尚无依据，待实测。

## 0.3 数值标注的含义

| 标注 | 含义 | 改动它的条件 |
|---|---|---|
| `[实测]` | 原型上跑过，手感或平衡已验证 | 需要重新实测 |
| `[推导]` | 由公式和其他数值算出，不是独立参数 | 改上游参数即可，不要直接改它 |
| `[占位]` | 文档 v1 未定义，实现时临时填的 | 随时可改，改前请补测试 |

## 0.4 遇到冲突

以**更靠后的章节**为准，并报告矛盾点。

# 第一部分 · 技术架构（硬约束）

## 1.1 分层

严格单向依赖。判断依据：**如果 A 系统删掉后 B 还能编译，那 B 不依赖 A。**

```
第 5 层  流程层   结局判定 · 幸存者 · 事件调度（尸群迁移/天气/广播）
                  ↓ 只能向下依赖
第 4 层  交互层   背包 · 搜刮 · 制作 · 烹饪 · 战斗 · 投掷 · 封锁 · 睡眠
                  ↓
第 3 层  实体层   玩家控制器 · 丧尸 AI · 听觉组件 · 伤势
                  ↓
第 2 层  规则层   声音传播 · 生存需求 · 熟练度 · 天气
                  ↓
第 1 层  地基层   游戏时钟 · 事件总线 · 数值修正管线 · 数据资产 · 存档序列化 · 地图图数据
```

**第 1–3 层必须能脱离渲染引擎运行。** 原型里这一点是靠「零 UnityEngine 引用」做到的，
所有规则都能在纯 CLI 下跑单元测试。这不是洁癖，是唯一能在改数值时不引入回归的办法。

## 1.2 事件总线

```csharp
public interface IGameEvent { }
public static class EventBus {
    public static void Subscribe<T>(Action<T> handler) where T : IGameEvent;
    public static void Unsubscribe<T>(Action<T> handler) where T : IGameEvent;
    public static void Publish<T>(T evt) where T : IGameEvent;
}
```

| 事件 | 发出者 | 主要订阅者 |
|---|---|---|
| `SoundEmitted` | 任何发声行为 | 声音系统、音效 |
| `SoundHeard` | 声音系统 | 听觉组件（丧尸 AI / 玩家 UI） |
| `PortalStateChanged` | 门窗交互、封锁 | 声音系统（缓存失效）、渲染 |
| `HourPassed` / `DayPassed` | 游戏时钟 | 需求、天气、流程调度 |
| `NeedChanged` | 需求系统 | UI |
| `PlayerDamaged` / `PlayerInjured` | 伤势系统 | UI、音效 |
| `ZombieDied` | 战斗 | 流程层（结局二计数） |
| `ItemAcquired` / `ItemConsumed` | 背包 | 笔记本、熟练度 |
| `SkillLeveled` | 熟练度 | 修正管线、UI |
| `SurvivorRecruited` | 幸存者 | 流程层、修正管线 |
| `ObjectiveProgressed` | 流程层 | 笔记本、UI |

**约束：** 处理器不得发出会导致同类事件递归的事件。深度超过 8 层记录警告。

## 1.3 数值修正管线

所有可变数值的唯一出口。**这是整个架构里最重要的抽象** —— 以后加任何新的加成来源，
都不需要改动任何原有系统。

```csharp
public static class ModifierPipeline {
    public static float Query(string key, float baseValue, int ownerId);
    public static void Register(string key, IModifier modifier);
    public static void Unregister(string key, IModifier modifier);
}
public interface IModifier {
    int Priority { get; }        // 低的先执行
    ModifierMode Mode { get; }   // Additive / Multiplicative / Override
    float Apply(float current, int ownerId);
}
```

**执行顺序：先全部 Additive，再全部 Multiplicative，最后 Override。**

**⚠ 实测教训：** 屏息最初写成 Override（把听觉阈值直接覆盖为固定值），
结果**听觉熟练度的收益被一笔抹掉** —— 练到 Lv5 和 Lv0 屏息后一样。
凡是「在当前值上再改善一点」的效果，必须用 Additive/Multiplicative，不能用 Override。
Override 只用于「无视一切，就是这个值」的场合。

**修正来源：** 熟练度、装备、负重、伤势、buff、幸存者加成、天气。全部注册到同一管线。

**已在用的 key：**
`sound.footstep` · `hearing.threshold` · `hearing.localization` · `stamina.run_cost` ·
`stamina.climb_cost` · `stamina.jump_cost` · `hold_breath.stamina_cost` · `move.run_speed`

所有静态配置用 ScriptableObject，不写在代码里：

## 1.5 存档

**单存档、随时保存、死亡删除、JSON、版本号写进存档头**，不兼容时明确提示而不是崩溃。

需要序列化：游戏时间 · 玩家（位置/朝向/生命/体力/需求/伤势/熟练度经验/背包/装备）·
所有丧尸（ID/类型/位置/生命/行为状态/目标点）· 所有 Portal 状态 ·
物资容器的**已被拿走什么**（不是记录全部内容）· 已招募幸存者 · 已完成的结局前置 ·
笔记本内容 · 已解锁配方 · 天气与事件调度进度。

`[实测]` **Portal 只记录与出厂状态不同的那些。** 存档体积小一个数量级，
而且改了地图之后旧存档仍能读进来（多出来的 Portal 用出厂值）。

# 第二部分 · 设计支柱

这四条决定所有取舍。**当某个设计选项与支柱冲突时，砍掉这个选项。**

### 支柱一：声音是唯一的通货
玩家的每个动作都有噪音代价。跑得快就吵，搜得快就吵，砸门就更吵。
**推论：** 任何新机制加入前先问——它有噪音代价吗？没有的话，它凭什么存在？

### 支柱二：世界是有限的，并且会被永久改变
丧尸有限、物资有限、不刷新。今天清掉的走廊明天真的是空的。
**推论：** 不做任何形式的刷新式重复内容。

### 支柱三：玩家应该能在脑内推演
声音传播、丧尸反应、需求消耗速率全部是确定性的。没有隐藏的随机数决定生死。
**推论：** 死亡永远是玩家能复盘的。「我不该那时候跑」而不是「我运气不好」。
**实现要求：** 一切随机（定位误差、腹泻概率、游荡目标）必须走**可复现的种子随机数**，
不能用系统 Random —— 否则存档读档后世界会变，玩家的推演就白费了。

### 支柱四：三十天是一条下坡路
难度不来自敌人变强，来自资源变少、水源断绝、丧尸重新分布。

## 2.1 一句话与核心循环

你是唯一一个睡过头的学生。醒来时，学校已经不是学校了。

```
白天：规划 → 潜行外出 → 搜刮/推进目标 → 天黑前返回据点
夜晚：处理需求（吃/喝/做饭/治伤）→ 睡觉 → 或冒险夜行
```

玩家反复做的那件事：**在有限的时间和噪音预算内，决定今天去哪、拿什么、什么时候撤。**

## 2.2 三幕

| 幕 | 天数 | 主题 | 玩家状态 |
|---|---|---|---|
| 一 | 1–5 | 求生 | 只有宿舍楼。任何一只丧尸都是致命威胁 |
| 二 | 6–18 | 立足 | 走出宿舍楼。解决水与食物，获得第一件武器，发现三条结局线索 |
| 三 | 19–30 | 抉择 | 物资枯竭，尸群迁移。选定一个结局全力推进 |

**第 8 天自来水停供**是一幕到二幕的推力。**第 15 天首次尸群迁移**是二幕到三幕的推力。

# 第三部分 · 声音系统（核心规则层）

> 这是全作的地基。潜行、丧尸 AI、昼夜、投掷、静步与听声熟练度全部建立在它之上。
> 它必须在其他系统之前实现，且不依赖任何上层系统。

## 3.1 它知道什么、不知道什么

**知道：** 一张地图连通图、一个只读游戏时钟、一个数值修正管线。
**不知道：** 丧尸、玩家、背包、UI 的存在。所有听者通过统一的 `HearingComponent` 接入。

## 3.2 核心公式

```
到达响度 = 源响度 − 距离衰减系数 k × 路径长度 − Σ(路径上所有 Portal 的衰减)
```

**路径长度是声音实际绕行的距离，不是直线距离。**

| k | 值 | 说明 |
|---|---|---|
| 室内 | 2.0 / 米 | |
| 室外 | 1.2 / 米 | 开阔地衰减更慢 |
| 夜间 | 全局 × 0.7 | 声音传得更远，等效距离 +43% |

夜间系数从时间系统读取，**必须是随时间平滑变化的曲线**，避免 19:00 整点声音突然变远。

## 3.3 数据结构

**`SoundEvent`**（发出后不可变）：`worldPosition` · `nodeId` · `loudness`(0–150) ·
`category`(Footstep/Impact/Voice/Gunshot/Ambient/Door) · `emitterId`(-1=无主) ·
`timestamp` · `chainDepth`(连锁层数)

`category` **不影响传播**，只影响听者的解读（UI 图标、丧尸对 Voice 的特殊处理）。

**`SoundNode`**：`id` · `bounds` · `isOutdoor` · `buildingId` · `floor` · `portals[]`

**`SoundPortal`**：`id` · `nodeA/nodeB` · `position` · `type` · `state` · `attenuation`(查表)

**`state` 是运行时可变的。** 玩家关门 → 木门衰减从 5 变 45。这是玩家控制声音传播的
主要手段，也是整个潜行玩法的核心交互。状态变化必须发 `PortalStateChanged` 让缓存失效。

**`HearingComponent`**：`threshold` · `localizationSkill` · `selfEmitterId`
**丧尸和玩家共用同一个组件。** 这是本系统最重要的架构决策——避免两套并行的听觉逻辑不一致。

## 3.4 传播算法

在 Portal 图上跑 **Dijkstra**，代价 = 累计衰减量。

```
1. 起始节点的入口点 = 声源位置本身，累计衰减 = 0
2. 优先队列按累计衰减升序展开
3. 从节点 N 经 Portal P 到节点 M：
     段长 = distance(N的入口点, P.position)
     新累计衰减 = 当前累计 + k × 段长 + P.attenuation
4. 剪枝：若 源响度 − 新累计衰减 < GLOBAL_MIN_THRESHOLD，不再展开
5. 每个节点只保留衰减最小的那条路径（自动实现「多通道取最优」）
```

`GLOBAL_MIN_THRESHOLD` = 全场景所有听者阈值的最小值。**这个剪枝是性能的关键。**

**听者结算**（图搜索只给到节点入口，还要加节点内的最后一段）：

```
若 听者节点 == 声源节点：到达响度 = 源响度 − k × distance(声源, 听者)
否则：              到达响度 = 该节点入口响度 − k × distance(入口Portal, 听者)
```

这一步解决了纯图模型的最大缺陷：**同一房间内贴脸和隔十米不再等价。**

**结算时机：** 事件驱动，不在 Update 里轮询。事件发出 → 立即跑一次传播 → 推给受影响节点内的听者。

## 3.5 边界情况

| 情况 | 处理 |
|---|---|
| 未加载区域 | **Portal 图始终全量常驻内存**（几百节点，几十 KB，不含美术）。传播不受加载状态影响 |
| 跨楼栋 | 正常走图。楼与楼通过室外节点相连，大门/破窗作为 Portal。枪声传遍半个校园是正确行为 |
| 室外传播 | 室外按功能区切成大节点，相邻用 `OpenAir`(衰减0) 连接。同节点内若有建筑遮挡，**额外扣 25**，射线判定 |
| 移动声源 | 脚步是离散事件，每步发一次。跑 0.35s / 走 0.7s 一次 |
| 自己的声音 | 按 `emitterId` 过滤自己的声纹显示，但**仍然会被丧尸听见** —— 否则潜行没有意义 |

`[实测]` **室外遮挡的射线判定必须由外部注入**（装配层传一个纯函数进来）。
声音系统属于规则层，不能反过来依赖碰撞世界，否则分层就破了。

| 楼梯口 | 10 | — | — | 60 |
| 通风口 | 30 | — | — | 80 |
| 室外相邻 `OpenAir` | 0 | — | — | — |
| 软隔断/帘子 | 20 | 25 | — | — |

`Blocked` = 被家具堵死（玩家封锁行为），**同时阻断通行**。
`[实测]` **同一个 Portal 状态同时管声音和通行，不能分成两套数据** ——
否则会出现「门关着但丧尸走得过去」这类几乎无法察觉的 bug。

## 3.8 听者反应

```
margin = 到达响度 − 最终阈值        （margin ≤ 0 直接丢弃事件）

反应延迟(秒)     = clamp(3.0 − margin × 0.06, 0.1, 3.0)
定位误差半径(米) = clamp(12.0 − margin × 0.25, 0.0, 12.0)
```

- 延迟期间：丧尸先停下、转头朝向大致方向，延迟结束才开始移动。
- 目标点 = 真实声源 + 误差半径内的随机偏移，**该偏移在接收事件时确定一次并固定**，
  不要每帧重算，否则丧尸会抖。
- **优先级覆盖：** 已在追某个声音时，新事件的 margin 必须**高出 8 以上**才切换目标。
  否则玩家连续投石会让丧尸原地反复抽搐。

这套公式自然产生了想要的效果：**近处的丧尸几乎立刻扑向准确位置，远处的迟疑几秒后
走向一个模糊方位。不需要为「远近」写特例。**

## 3.9 玩家听觉：范围模型

**⚠ v1 重大修订。** v1 给玩家的阈值是 25、丧尸是 10 —— 玩家的听力比丧尸差一倍多，
与「听力等级提升听力范围」的设定直接冲突。现改为：

```
可听半径 = (声源响度 − 听觉阈值) / k          阈值越低听得越远
```

| 听觉等级 | 阈值 | 丧尸脚步(48) | 追击低吼(55) | 蜷伏者呼吸(12) |
|---|---|---|---|---|
| Lv0 | 8.0 | **20.0m** / 屏息 22.0m | 23.5 / 25.5m | 2.0 / 4.0m |
| Lv1 | 6.8 | 20.6 / 22.6m | 24.1 / 26.1m | 2.6 / 4.6m |
| Lv2 | 5.6 | 21.2 / 23.2m | 24.7 / 26.7m | 3.2 / 5.2m |
| Lv3 | 4.4 | 21.8 / 23.5m | 25.3 / 27.0m | 3.8 / 5.5m |
| Lv4 | 3.2 | 22.4 / 23.5m | 25.9 / 27.0m | 4.4 / 5.5m |
| Lv5 | 2.0 | 23.0 / 23.5m | 26.5 / 27.0m | 5.0 / 5.5m |

- 初始阈值 **8**，只比丧尸的 10 好一点点 —— 玩家不是超人，只是没那么迟钝。
- **屏息在当前等级值上再减 4**（Additive，不是 Override，见 1.3 的教训）。
- 阈值下限 1。
- 对照：丧尸（阈值 10）听见玩家正常走路是 **5m**、奔跑 17.5m。**玩家有先手。**

### 三条实测结论

1. **`[实测]` 范围上限由声源响度决定，不由听力决定。**
   所以等级对「很轻的声音」影响巨大（蜷伏者呼吸 2m → 5m，两倍半），
   对「很响的声音」几乎无所谓（低吼 23.5m → 26.5m）。
   **练听力是为了听见那些几乎没有声音的东西** —— 这是个好性质，不用额外设计。
2. **`[实测]` 常态听不见蜷伏者呼吸。** 2m 的半径抵不过「耳朵在 1.65m、它趴在地上」
   的高度差。必须屏息。
3. **`[实测]` 屏息收益在高等级后封顶**（阈值贴到下限），其价值自然从「听得更远」
   转为「自己完全不发声」。这个转变是免费的。

### 声源响度是怎么定出来的

`[实测]` 丧尸巡逻脚步定 **48**，是按「初始可听 20m」反推的：`(48−8)/2 = 20`。
**瓶颈从来不是「穿墙扣得太多」，而是声源太轻** —— 定 30 时隔一个楼梯口只剩 5.5m，
等于什么都听不见。48 比玩家奔跑（45）还响，这是有意的：**丧尸不在乎自己发出声音，玩家在乎。**

| 场景 | 玩家 Lv0 可听 |
|---|---|
| 同一房间/走廊 | 20.0m |
| 隔一扇**开着**的木门（衰减 5） | 17.5m |
| 隔一个楼梯口（衰减 10） | 15.0m |
| 隔一扇**关着**的木门（衰减 45） | **听不见** |

**关着的门仍然是硬屏障，这一条不能动。**

## 3.10 声纹（玩家听觉的呈现）

- **常态也显示。** 阈值本身已经是过滤器：初始阈值 8 只有 20m 内的动静过得来。
  屏息的价值是「把范围再拉开 2m + 自己完全不发声」，而不是「才能看见」。
- **只显示丧尸发出的声音**（脚步、低吼、巡逻动静）。自己扔的石头、开的门不显示 ——
  你知道自己干了什么，不需要 UI 告诉你。
- **形式：挂在声源头顶的世界坐标标记，穿墙可见。** 不是屏幕中心的方向指示环。
  做法是把声源世界坐标投影到屏幕再画图标；声源跑到画面外时收到屏幕边缘，
  变成一个指向它的三角。
- **图标矢量绘制**（脚印 / 声波弧 / 爆点 / 门），不用文字标签 —— 文字在小尺寸下认不出来。
  新响起的标记带一圈外扩涟漪。
- **明显度随 margin 变化：** 强度 = `clamp(margin / 26, 0, 1)`，决定标记半径（8→16px）、
  不透明度与描边粗细。贴脸的动静又大又亮，勉强够到阈值的只是一个淡淡的小点。

**⚠ 待决策：** 现在等级只影响**范围**，不影响**精度** —— 标记直接给精确位置，
等于白送了 10.2 里听觉 Lv5 的「近乎精确定位」。
建议改为：Lv1–3 只给方向（屏幕边缘三角）、Lv4 起头顶显示、Lv5 才去掉位置误差。

## 4.1 时间

| 项 | 值 |
|---|---|
| 1 游戏小时 | 85 秒真实 `[占位]` |
| 白天 | 07:00–19:00（17 分钟） |
| 夜晚 | 19:00–07:00（17 分钟） |

**光照**同样平滑过渡。19:00 后室内没有光源则接近全黑，必须用手电。

> 第二幕可能让玩家频繁陷入「来不及回家」的焦虑。备选值 20 或 22 分钟。
> **这个参数必须放在配置文件里。**

## 4.2 夜行

**收益：** 多出一整个 17 分钟窗口 · 丧尸视觉半径减半（听觉不变）· 部分丧尸夜间回到
固定聚集点，某些区域反而空旷。

**代价：** 声音传播距离 +43% · 必须用手电且手电让丧尸视觉半径 ×1.8 ·
放弃精力充沛 buff · 整夜未睡则次日困乏接近满值、几乎无法奔跑。

**这是一个明确的借贷：今晚多干一轮活，明天付利息。**

## 4.3 天气

30 天中安排 6 个雨天：**第 9、13、17、22、25、28 天。天气必须固定，不随机** ——
玩家应该能提前规划。

雨天：雨声掩盖脚步（全局玩家响度 −30%），**是最适合行动的日子**；但视野降低，
丧尸也更难被听见；是唯一的雨水收集窗口。

# 第五部分 · 玩家

## 5.1 移动与姿态

| 姿态 | 速度 | 基础响度 |
|---|---|---|
| 站立行走 | 2.4 m/s | 20 |
| 奔跑 | 4.6 m/s | 45 |
| 蹲行 | 1.2 m/s | 10 |
| 贴墙移动 | 1.0 m/s | 14 |
| 屏息移动 | 蹲行 × 0.5 | 0 |
| 静止 | 0 | 0 |

```
最终响度 = 基础响度 × (1 − 静步减免) × (1 + 0.5 × 负重比)
```

`[实测]` **移动向量只在长度超过 1 时归一化。** 键盘斜向走（长度 √2）被压回 1，
而手柄/摇杆的模拟量（0~1）得以保留 —— 直接无条件归一化会让模拟量输入失效。

## 5.2 潜行动作

**贴墙（单击切换，不是按住）**
- 靠近墙面按键进入，**背贴墙面，朝向沿墙走向**，视角切第三人称，仍可投掷。
- `[实测]` **朝向必须沿墙，不能朝墙外。** 走廊只有 2.6m 深，朝墙外等于脸贴 2 米外的
  另一面墙，第三人称什么也看不见。掩体系统的通行做法就是「背贴墙、视线沿墙」。
- `[实测]` **只有离开进入时那面墙才自动解除。** 走廊里任何位置都离某面墙不到 1.35m，
  只判「附近有没有墙」的话永远解除不了。
- 第三人称相机放在身后并往开阔侧推、抬高。**相机朝向必须与第一人称完全一致**
  （只是位置退到身后）—— 用 `lookAt` 盯身前一点会让光轴与投掷方向越岔越开，准星对不上落点。

**探头（侧身）**
- 站立/蹲下/贴墙时都可以左右侧身。侧身时移动速度为 0（贴墙时仍可沿墙挪）。
- 身体倾约 30°，但**第一人称里唯一看得见的线索是画面翻滚，翻滚只给一半（15°）**，再多会晕。
- `[实测]` **必须加 0.12 秒平滑过渡。违和感的主要来源是瞬间切换，不是角度大小。**
- `[实测]` 平滑之后「侧到一半」成为有效状态：**探出去多少就暴露多少** ——
  被发现半径在 1.0 与 0.35 之间按侧身量插值。
- `[实测]` **侧身时眼位跟着横向探出去**，投掷起点、听觉位置、被发现判定
  全部按探出后的头部位置算。所以「贴掩体侧头扔石头」是成立的动作，代价也如实生效。

**屏息**
- 自身响度降为 0；听觉阈值在当前等级值上 −4；开启声纹显示；消耗体力 3/秒。
- 移动速度限制为蹲行的 50%（**允许缓慢移动** —— 完全禁止会让侦查变成「停下来读地图」，破坏节奏）。

## 5.3 交互

| 动作 | 快速版 | 缓慢版 |
|---|---|---|
| 开门/开窗 | 瞬间，响度 35 | 按住 2.5 秒，响度 12 |
| 关门/关窗 | 瞬间，响度 30 | 按住 2.0 秒，响度 10 |
| 翻找容器 | 4 秒，响度 40 | 9 秒，响度 15 |

**缓慢版是默认应该被鼓励的做法。快速版存在的意义是「来不及了」。**

**封锁（Barricade）：** 对门/窗使用建材，Portal 状态改为 `Blocked`。
需要建材 1–3、作业 20–60 秒，期间持续产生响度 50 的噪音。可拆除，同样耗时且吵。

## 5.4 投掷

| 物品 | 落点响度 | 特殊 |
|---|---|---|
| 石头 | 45 | 校园内随处拾取 |
| 玻璃瓶 | 75 | 碎裂，吸引范围大 |
| 发令枪 | 110 | 一次性，结局二布置阶段的关键道具 |
| 闹钟（可制作） | 60，持续 15 秒 | **定时触发，唯一能做到「延迟引怪」的道具** |

**闹钟是潜行深度的关键。** 它让玩家可以规划：提前在 A 点放一个 90 秒后响的闹钟，
自己去 B 点等待。

**投掷预览（必须做）：** 按住蓄力时显示弹道点阵 + 落点标记 + **引怪半径圈**。
半径 = `(落地响度 − 丧尸阈值) / k`，直接告诉玩家「这一下会惊动多大范围」（支柱三）。
UI 上同时给出落点所在节点名与半径数值，并注明**圆圈只是同一空间内的上界，隔墙隔门会更短**。

`[实测]` 两个必须遵守的实现细节：
1. **预览与实弹必须共用同一个定步长积分器。** 预览用固定步长、实弹用逐帧变长 dt 的话，
   两条轨迹根本不是同一条，玩家看到的抛物线和石头真正落的地方对不上。
2. **落点必须取「接触点」，不能取穿透之后的位置。** 石头落在四楼地板上时，
   穿透点在楼板下方，会被判成从三楼发出 —— **在自己脚边扔一块石头会去惊动楼下的丧尸。**
   用二分法求出最后一个未接触的点。

## 5.5 视觉与被发现

- 感知锥角 110°，半径 14m（白天）/ 7m（夜间）/ 12.6m（夜间持灯）
- 蹲下 ×0.6，探头 ×0.35（按侧身量插值）
- 有遮挡则完全看不见（射线检测，每只丧尸每 0.2 秒一次，只对半径内的丧尸执行）
- 进入视野不是立即发现，有 **0.8 秒识别条**，期间玩家可以退回掩体

## 5.6 跳跃与情境翻越（文档外新增，待拍板）

**⚠ v1 没有跳跃。** 主文档 4.1 的姿态表只有走/跑/蹲/贴墙/静止。以下是应需求新增的。

一个键两种行为：**正前方有可翻越的边缘就翻越，没有才起跳。**

翻越判定：沿正前方每 0.2m 采样，找第一个「顶面高出脚下 0.30–1.45m、
且上方有 0.95m 净空」的位置。0.95m 是按蹲姿通过算的，正好能钻过 1.0m 高的窗洞。

| 情形 | 结果 |
|---|---|
| 床铺（0.55m）、书桌（0.75m） | 翻上去 |
| 打开的窗（窗台 1.0m，窗洞净空 1.0m） | 翻出去 |
| 关着的窗 | 翻不了（窗扇是实体，挡人也挡声） |
| 3.2m 的墙 | 翻不了，退化为原地起跳 |
| 0.2m 的台阶 | 低于阈值，本来走上去就行，不触发 |

| 数值 | 值 | 来源 |
|---|---|---|
| 攀爬/翻窗体力消耗 | −12 / 次 | **文档内**（主文档 3.3） |
| 翻越响度 | 30 | **文档内**（翻窗，声音规格 6.1） |
| 重力 | 18.0 | `[占位]` 文档外 |
| 起跳初速 | 4.2（跳起约 0.49m） | `[占位]` 文档外 |
| 跳跃体力消耗 | 6 | `[占位]` 文档外，取攀爬的一半 |
| 落地响度 | 35 | `[占位]` 文档外 |
| 空中转向能力 | ×0.65 | `[占位]` |
| 郊狼时间 | 0.12s | `[占位]` |

`[实测]` **玩家的水平与垂直运动必须拆开处理。** 加了跳跃之后不能再每帧把角色硬吸附到
地面，需要独立的重力积分、天花板阻挡、走下边沿转入下落。丧尸不跳，仍走吸附式移动。

# 第六部分 · 生存需求

## 6.1 生命条与挤占机制

**生命条总长 100，长度固定不变。** 饥饿与口渴各自在右端生成挤占区：

```
[========= 可用生命 =========][== 饥饿 ==][= 口渴 =]
```

| 规则 | 说明 |
|---|---|
| `可用生命上限 = 100 − 饥饿挤占 − 口渴挤占` | |
| 当前生命不能超过可用上限 | 挤占增长会**压低**当前生命 —— 这就是饿死渴死的机制 |
| 可用上限降至 0 | 死亡 |
| 进食/饮水**立即**减少挤占，上限立即恢复 | |
| **但当前生命不会因此回血** | 挤占解除只是解锁了上限，受过的伤要单独治 |

| 需求 | 0 涨满 100 | 折算 | 说明 |
|---|---|---|---|
| 口渴 | 30 游戏小时 | 约 2.5 天 | 单独不管必死 |
| 饥饿 | 96 游戏小时 | 4 天 | 涨得慢但一旦上去很难压下 |

两者相加超过 100 时取 100（死亡）。实际上玩家通常在第 25 小时左右因两者叠加而死。

**恢复量：**

| 物品 | 减少口渴 | 减少饥饿 | 备注 |
|---|---|---|---|
| 瓶装水 500ml | 25 | 0 | |
| 煮沸的水 | 22 | 0 | |
| 未处理的水 | 25 | 0 | **40% 概率获得腹泻** |
| 饼干/面包 | 3 | 12 | |
| 泡面（干吃） | −5 | 15 | 加重口渴 |
| 泡面（泡开） | 8 | 25 | 需要热水 |
| 烹饪食物（基础） | 5 | 35 | |
| 烹饪食物（熟练度 5） | 8 | 50 | |

**腹泻：** 口渴增速 ×2，持续 8 小时。自愈或药物。

## 6.2 体力条与困乏

**体力条总长 100，由困乏从右端挤占。** `可用体力上限 = 100 − 困乏挤占`

- 困乏清醒时 **+5 / 游戏小时**（20 小时挤满），睡眠时 **−12 / 游戏小时**
- 因此每天必须睡约 7–8 小时

| 行为 | 体力 |
|---|---|
| 奔跑 | −8 / 秒 |
| 屏息 | −3 / 秒 |
| 攀爬/翻窗 | −12 / 次 |
| 近战挥击 | −6 / 次 |
| 站立不动 | +6 / 秒 |
| 蹲下不动 | +9 / 秒 |

体力归零：无法奔跑，移动速度 −30%，**并产生响度 25 的喘息声** ——
体力耗尽在潜行时是致命的。

## 6.3 睡眠

**安全睡点三个条件缺一不可：**
1. 所在房间的所有 Portal 处于 `Closed` 或 `Blocked`
2. 房间内**及相邻节点**没有丧尸
3. 有床或睡袋

`[实测]` **判定必须逐条给出失败原因并显示给玩家**（「还有门窗没关上」「隔壁有丧尸」
「附近没有床」），否则玩家只会看到「睡不了」而不知道要做什么。

**睡眠过程：** 选择时长（最多 10 小时）→ 时间加速推进 → 饥饿口渴**正常累积** →
若有 `margin > 15` 的响度到达玩家节点，**睡眠中断，惊醒，且不获得当次睡眠的任何 buff**。
中断后可以重新入睡。

**精力充沛 buff：** 22:00 之前入睡且连续睡眠 ≥ 6 小时未被中断 →
次日 24 小时内困乏增速 −25%、体力回复 +15%。

**这个 buff 是玩家规划一天的主要动机 —— 它把「天黑前回家」变成了有正反馈的行为。**

# 第七部分 · 丧尸

## 7.1 总体

- **全校丧尸总数约 320 只，固定，不刷新。**
- 每只有唯一 ID 和持久状态（位置、健康、当前行为），死亡永久移除。
- 未加载区域的丧尸以简化形式模拟（只维护「所属节点 + 目标节点」），玩家进入时还原。

## 7.2 类型（只有三种，不要增加）

| | 游荡者 (85%) | 蜷伏者 (10%) | 奔行者 (5%) |
|---|---|---|---|
| 生命 | 100 | 100 | 60 |
| 游荡速度 | 1.0 m/s | — | 1.2 m/s |
| 追击速度 | 3.2 m/s | 同游荡者 | **5.4 m/s** |
| 听觉阈值 | 10 | 6 | 6 |
| 视觉半径 | 14m | 14m（起身后） | 18m |
| 出现时机 | 全程 | 全程 | **第 12 天后** |

**蜷伏者：** 静止趴伏在暗处、课桌下、床下、储物柜内，远看像尸体。
**只有当声源在 8 米内才起身。** 作用是让玩家不敢放松地穿过看似安全的房间。
屏息时能听到它极轻微的呼吸声（响度 12 的持续 `Ambient` 事件）。

**奔行者：** 比玩家快，**不能靠跑摆脱，只能靠拐角断视线或提前避开**。
第 12 天前完全不出现，作为难度递进的标志。

`[实测]` **头部命中伤害 ×4。** 调查状态的移动速度 = 游荡速度 × 1.6 `[占位]`
（文档只定义了游荡与追击两档，中间态缺失）。

## 7.3 巡逻声（v1 未定义，本版新增）

**未趴伏的丧尸只要在移动就发出响度 48 的拖行脚步；趴伏的蜷伏者不发。**

这回答了 v1 第 13.1 节的待定问题 4：**玩家能听见丧尸的常态动静。**
详见 3.9 的范围表。

`[实测]` **同类之间只有低吼会互相引，脚步与呼吸一概忽略。**
否则 A 的脚步引来 B，B 一走又发出脚步引来 C，整层楼会自激成一锅粥。
这些声音的存在意义是让玩家听见，不是让丧尸互相听见。

`[实测]` **移动判定必须放在帧末。** 「本帧是否移动了」要拿当前位置和**上一帧末尾**
的快照比 —— 放在帧首比的话两者永远相等，脚步声一次都发不出来。

## 7.4 行为状态机

```
游荡 ──听到声音──> 警觉(转向,延迟) ──延迟结束──> 调查(走向目标点)
                                                  │
调查 ──到达目标点──> 搜索(原地徘徊 8~15 秒) ──超时──> 返回游荡
                                                  │
任意状态 ──看见玩家(识别条满)──> 追击 ──失去目标 6 秒──> 搜索
```

**追击时丧尸持续发出响度 55 的低吼**（每 1.5 秒一次）——
这会引来更多丧尸。**这是本作最危险也最刺激的机制。**

**警觉状态下听觉阈值降到 6**（经修正管线，不写死）。

## 7.5 连锁警戒上限

- 单次连锁最多传播 **2 层**（A 引来 B，B 引来 C，C 不再引人）
- 同时处于追击状态的丧尸全场上限 **12 只**，超过时最远的转为搜索
- **这两个数字必须可配置**

## 7.6 寻路

丧尸在 Portal 图上找路，**只走 `passable` 的连接**（Closed/Blocked 挡人）。

`[实测]` **楼梯必须给四个顺序路点**：走道上对齐梯脚 → 梯脚 → 梯顶 → 上层走道。
只给「梯段中点」的话，丧尸会从走道斜切过去撞在梯段侧面，因为台阶侧壁高度超过
可跨越高度爬不上去。

**⚠ 待决策：丧尸会不会撞门？** v1 未定义。目前关上的门对丧尸是**绝对屏障**，
这让「关门」变成零代价的万能解。响度表里有「撞门 70」，但没有对应的行为规则。

## 7.7 尸群迁移

第 **15、21、26** 天各触发一次（可配置）。全校丧尸的游荡区域重新分配。
迁移当天有明显预兆：清晨大量丧尸同向移动，可以从窗口看到。
**迁移不产生新丧尸，只是重新分布。**

# 第八部分 · 战斗与伤势

## 8.1 武器

**近战为主，武器稀少。第一幕基本没有武器。**

| 武器 | 获取 | 伤害(头/身) | 挥击响度 | 体力 | 耐久 |
|---|---|---|---|---|---|
| 拖把杆 | 宿舍楼 | 25 / 8 | 40 | 5 | 30 |
| 棒球棍 | 体育器材室 | 55 / 20 | 55 | 6 | 80 |
| 消防斧 | 各楼消防箱 | 90 / 40 | 65 | 10 | 60 |
| 钢叉 | 保安室 | 40 / 15 | 50 | 7 | 120 |
| 警棍 | 保安室 | 45 / 18 | 45 | 5 | 150 |
| 菜刀 | 食堂 | 60 / 25 | 35 | 4 | 40 |

**没有枪。** 一所中国学校不该有枪。发令枪是纯噪音道具，不造成伤害。
**这个限制是设计上的优势 —— 它保证了游戏永远不会变成射击游戏。**

## 8.2 战斗规则

- 攻击有前摇（0.4–0.9 秒，依武器），**期间不能取消**
- **背后偷袭：对未察觉的丧尸从背后攻击必定处决**，响度只有 30，不消耗耐久
- **处决是玩家清理丧尸的主要手段。正面战斗几乎总是错误选择**
- 正面被抓 → 挣脱 QTE，失败则被咬；同时被 2 只以上接触 → 必然被咬

## 8.3 伤势

**死亡不应该是瞬间的。玩家应该有机会犯错并挽回，但要付出代价。**

| 伤势 | 来源 | 效果 | 治疗 |
|---|---|---|---|
| 出血 | 被抓、被咬 | 每秒 −0.8 生命，持续至处理 | 绷带 |
| 骨折 | 高处跌落、被扑倒 | 移动 −40%，奔跑时每秒产生响度 50 的痛呼 | 夹板 + 静养 12 小时，或医务室幸存者 |
| 感染 | 被咬，**60% 概率** | 潜伏 6 小时后每小时生命上限 −3，累积至死 | **抗生素**（全校 4 支），或医务室幸存者 + 酒精（60%） |
| 腹泻 | 喝未处理的水 | 口渴增速 ×2，持续 8 小时 | 自愈或药物 |

**抗生素只有 4 支，而感染概率是 60% —— 玩家最多能承受约 6 次被咬。
这个数字定义了整局游戏的容错额度。**

## 8.4 死亡

生命值归零 → 死亡 → 存档删除 → 返回主菜单。无复活、无检查点。

**幸存者笔记（跨局继承，建议实装并默认开启）：** 死亡后，本局已探索过的地图区域、
已发现的配方、已见过的丧尸类型留在一本笔记里，新一局可查阅。
**不提供任何数值优势**，只是省去重复摸索。

理由：一局 10 小时以上的永久死亡，如果每次都要从零重新摸清地图布局，
大部分玩家在第二次死亡后会退坑。**地图知识本来就是「玩家脑子里的东西」，
把它写下来不改变难度，只是减少重复劳动。** 可做成开关，硬核玩家可关掉。

# 第九部分 · 熟练度

六项技能，各 1–5 级。**使用中成长，但只有有意义的使用才计入。**

## 9.1 反刷分设计（重要）

不要按「行为次数」给经验，按**有效行为**给：

| 技能 | 计经验的条件 |
|---|---|
| 静步 | 只有在**某只丧尸的听觉范围内**成功移动而未被察觉才计。原地蹲着绕圈不给 |
| 听觉 | 只有屏息状态下，声纹指向了一个**之前未知的丧尸**才计 |
| 体能 | 只在体力降至 30% 以下时的行动计 |
| 敏捷 | 只在被追击状态下的翻越、冲刺计 |
| 烹饪 | 每个配方**首次**制作给大量经验，重复递减（第 5 次后归零） |
| 手艺 | 同烹饪，按配方计 |

## 9.2 等级效果

| 技能 | Lv1 | Lv2 | Lv3 | Lv4 | Lv5 |
|---|---|---|---|---|---|
| **静步** | 响度 −8% | −16% | −24%，解锁「极慢步」(0.6m/s，响度 4) | −32% | −40%，蹲行不再触发地面杂物声 |
| **听觉** | **阈值 8→6.8** | 6.8→5.6，声纹显示丧尸类型 | 5.6→4.4 | 4.4→3.2，声纹穿透一层 Portal | 3.2→2.0，近乎精确定位 |
| **体能** | 体力上限 +10 | +20，奔跑消耗 −10% | +30，困乏增速 −10% | +40，消耗 −20% | +50，体力耗尽不再喘息 |
| **敏捷** | 奔跑 +5% | +10%，翻越更快 | +15%，解锁攀爬管道 | +20% | +25%，跌落不再骨折 |
| **烹饪** | 恢复量 +10% | +20%，解锁 3 配方 | +30%，食物不易腐 | +40%，解锁 3 配方 | +50%，解锁 buff 类食物 |
| **手艺** | 搜刮速度 +15% | +30%，解锁闹钟 | +45%，解锁修理 | +60%，封锁更快更安静 | +75%，武器耐久消耗减半 |

**⚠ v1 修订：听觉一列改为阈值（= 可听范围），不再是「方向误差百分比」。**
原因见 3.9。方向精度的分级归入 3.10 的待决策项。

**所有效果通过数值修正管线生效。技能等级不写进任何业务逻辑，业务逻辑只向管线要最终值。**

# 第十部分 · 物资、背包与制作

## 10.1 背包与容器

**格子背包。玩家背包和地上的书包在规则上是同一个东西 —— 同一个 `Grid` 类。**

| 容器 | 尺寸 | 获取 |
|---|---|---|
| （无背包） | — | **开局状态。** 只有 6 格快取栏 |
| 小书包 | 5×4 = 20 格 | 宿舍衣柜里常见，第一个目标 |
| 学生书包 | 5×4 = 20 格 | 宿舍楼/教学楼常见 |
| 战术背包 | 6×5 = 30 格 | 保安室，唯一 |
| 登山包 | 6×6 = 36 格 | 体育器材室，唯一 |

**六格快取栏**：始终可用，不依赖背包，数字键 1–6 直接使用。
**开局没有背包** —— 找到第一个小书包是第一幕的第一个真正目标。

### 格子规则

- 每件物品占 w×h 格，**放不下时自动尝试旋转 90°**
- 可堆叠物品（石头 8、绷带 3、布 5、电池 4、闹钟零件 3）先并进已有的堆
- **「放不下」必须分两种情况提示**（这是可用性问题，不是文案问题）：

| 情况 | 判据 | 提示 |
|---|---|---|
| **背包已满** | 空格总数 < 物品所需格数 | 「背包已满（还剩 N 格，X 需要 M 格）」 |
| **请整理背包** | 空格够，但拼不出连续区域 | 「请整理背包（还剩 N 格，但拼不出 X 需要的连续区域）」 |

**整理**按钮按体积从大到小重排，把碎片挤掉。

### 负重

**负重独立于格子。基础上限 20kg，背包自重计入。**

```
负重比 r = 当前重量 / 上限
脚步响度 × (1 + 0.5r)      体力消耗 × (1 + 0.8r)      奔跑速度 × (1 − 0.25r)
```

超过上限 100% 时无法奔跑。**背得多就吵、就累、就慢** —— 支柱一在物资系统上的体现。

## 10.1c 搜刮

**两种取物方式：**

1. **地上散落的物品** —— 走近按 F 直接进背包，自动排列。
2. **容器** —— 走近按 F 打开，**物品一件一件点亮**（三角洲式），点亮一件才能点它拿走。

| 翻找方式 | 操作 | 总时长 | 响度 |
|---|---|---|---|
| 快速 | 轻点 F | 容器基准时长 | **40** |
| 缓慢 | 按住 F | 基准 × 2.25 | **15** |

**逐个点亮不是装饰：它把「搜刮」变成一段有长度的、可以被打断的过程。**
你在翻箱子的时候是聋的也是瞎的，而箱子越大翻得越久。

**打开背包时游戏不暂停。** 搜刮和整理背包本身就是有风险的行为。

- **不刷新。** 拿走就没了
- 数量按「精打细算能撑到 30 天，浪费则撑不到 20 天」标定

| 保安室 | 钢叉、警棍、手电、对讲机、校园平面图、战术背包 |
| 体育器材室 | 棒球棍、发令枪、登山包、绳索 |

但省掉了手工填几百个容器的重复劳动。**稀有物资（抗生素、战术背包）必须写死在具体位置**，
否则「知道哪里有抗生素」这条知识就没有意义了。

## 10.3 水系统（第二幕的核心矛盾）

- 第 1–7 天：水龙头可用，无限接水（每次响度 30，需要容器）
- **第 8 天 00:00 自来水停供**，所有水龙头失效
- 此后水源：
  1. **瓶装水** —— 有限，总量约够 6 天
  2. **雨水收集** —— 需制作收集器（容器 + 塑料布），放露天处，**下雨天才有产出**
  3. **可疑水源** —— 消防水箱、水池、马桶水箱。未处理直接喝 40% 腹泻，煮沸后安全
  4. **煮沸** —— 热源 + 容器，耗时 3 游戏小时，产生响度 20 的持续噪音

## 10.4 烹饪

**热源：** 食堂燃气灶（最好）、酒精灯（实验楼）、篝火（可制作，但响度和光都很大）

| 配方 | 材料 | 饥饿恢复 |
|---|---|---|
| 煮水 | 水 + 容器 | — （净化可疑水） |
| 白饭 | 米 + 水 | 30 |
| 泡面 | 泡面 + 热水 | 25 |
| 煮鸡蛋 | 鸡蛋 + 水 | 18 |

**烹饪的代价：** 每次持续 20–40 游戏分钟，期间响度 25 的持续噪音，
**并且产生气味** —— 简化为：烹饪结束后 1 游戏小时内，该节点及相邻节点的丧尸听觉阈值 −3。

# 第十一部分 · 幸存者

## 11.1 设计约束

**不做跟随 AI，不做战斗 AI，不做寻路跟随。幸存者是固定在位置上的 NPC。**
这是为了让这个系统在单人开发的预算内可实现。

## 11.2 四名幸存者

| 代号 | 位置 | 需求 | 招募后提供 |
|---|---|---|---|
| 老周（保安） | 保安室内间（反锁） | 抗生素 ×1 + 食物 ×3 | 夜间据点警戒：睡眠不再被 margin<30 的声音中断 |
| 小林（学生） | 图书馆书库夹层 | 水 ×4 + 证明外面安全 | 协助搬运：负重上限 +8kg |
| 陈老师（物理） | 实验楼准备室 | 食物 ×2 + 手电 ×1 | 解锁「修理」配方，发电机故障率降低 |
| 医务室的人 | 医务室（藏在药柜后） | 只需找到并说话 | 可治疗骨折、加速感染治疗 |

## 11.3 招募流程

**发现**（环境线索）→ **接触**（对话说明需求）→ **满足需求** →
**迁移**（自行前往据点，过场处理，不做实际寻路，此后固定在据点某位置）

## 11.4 与结局的关系

结局二需要 ≥3 名 · 结局一中幸存者参与最后三夜守城（被他们守住的入口不会被突破）·
结局三（车辆）可带走所有已招募幸存者，**徒步逃离不能带走任何人** ——
这是它成为「最差结局」的原因。

# 第十二部分 · 目标与结局

三个结局互斥，一局只能达成一个。

| | 一 · 等待救援 | 二 · 净化 | 三 · 逃离 |
|---|---|---|---|
| 最早完成 | 第 30 天 | 约第 22 天 | 约第 9 天 |
| 难度 | 中 | 高（真结局） | 低–中 |
| 核心考验 | 资源可持续 + 最终守城 | 探索完整度 + 系统性准备 | 机械修复 + 一次成功突围 |
| 需要幸存者 | 否 | 是（≥3） | 否 |

## 12.1 结局一 · 等待救援

**触发：** 存活至第 30 天 07:00

- 第 1 天起可在多处找到收音机零件。**没有收音机就不会触发第 27 天事件**，
  玩家会莫名其妙地在第 30 天什么也没发生 —— 所以收音机应该在第一幕就被强引导
  （宿舍楼内有一台坏的，零件散落在校内）。
- 第 27 天 08:00 收到军方广播：直升机第 30 天 07:00 抵达，要求**启动并维持定位信标**。
- 信标位于**行政楼天台**。启动需要：发电机 + 柴油 ×2 + 信标装置。
- **信标一旦启动持续发出响度 90 的噪音，不能关闭。** 全校剩余丧尸开始向该建筑汇聚。
- 玩家必须在该建筑内**坚守三个夜晚**（27、28、29 夜）。
- 第 30 天 07:00 直升机抵达。

**设计意图：** 把「活满三十天」从数日子变成一场有明确高潮的攻防战。
玩家前 26 天所有的准备在这三夜集中兑现。

## 12.2 结局二 · 净化（真结局）

**前置条件（全部必须完成）：**
1. **封锁全部 6 个出入口**（正门、后门、东侧门、围墙破口 ×3）。
   每个需建材 ×N + 现场作业 90 秒（期间持续响度 55）
2. **招募 ≥3 名幸存者**
3. **修复广播系统**：广播室钥匙 + 发电机 + 柴油 ×3 + 广播设备零件 ×2 + 手艺 ≥3
4. **改造操场**：4 处可关闭闸口 + 打通一条从广播室到操场的引导路线（沿途门必须 Open）

**执行：** 广播室开启广播（响度 150，覆盖全校）→ 全校丧尸向广播室移动 →
**玩家必须在丧尸抵达前撤离，沿引导路线跑到操场** → 幸存者在玩家通过后依次关闭闸口 →
全部丧尸进入操场后关闭最后一道闸口。

**这是一段约 4 分钟的追逐段落。** 这是唯一一个把整局所有系统都用上的段落。
它应该很难，并且值得。

**执行前必须给玩家明确警告并允许取消。这不是一个可以试错的操作。**
**风险缓解：** 考虑允许「演习模式」（不开广播，仅测试路线跑通时间）。

## 12.3 结局三 · 逃离

- **3a 车辆逃离（较好）：** 车棚有报废电动摩托、校车。修复需零件 ×3 + 电瓶/柴油 +
  手艺 ≥2。修好后从正门驶出（正门必须未被封锁）。
- **3b 徒步逃离（最差）：** 从任一围墙破口离开。不需要任何物品，但破口周边有密集丧尸群。

**设计意图：** 这是「随时可以放弃」的出口，应该始终可用，让玩家在绝望时有选择。
片尾会明确告知玩家放弃了什么（例如「你没能带走任何人」），但**不做道德说教**。

## 12.4 目标的呈现

**玩家不通过任务列表得知这些。所有目标通过环境叙事发现：**
收音机广播 → 结局一 · 保安室的平面图 + 墙上字条 → 结局二 · 车棚的车 + 门卫室钥匙 → 结局三

UI 里有一本**笔记本**，记录已发现的线索、地图标记、配方。**它是被动记录，不给指引。**

## 13.4 场景加载

- 每栋建筑：独立场景，进入所属室外区域时异步加载，离开一定距离后卸载
- **声音连通图始终全量常驻**（纯数据，几十 KB）
- 未加载建筑内的丧尸以简化形式继续模拟，能正确接收声音并更新目标

## 13.5 房间节点标注

每个房间/走廊/楼梯间/室外分区挂 `SoundNodeVolume`，
每个门/窗/楼梯口/破洞挂 `SoundPortalLink`，编辑器烘焙工具导出为 `SoundGraph` 资产。

宿舍楼结构规整，**应做成可程序化生成的模板**，只手工放置物资和丧尸。教学楼同理。

`[实测]` **几何体与声音图必须由同一份布局推导出来。** 分成两份手工维护的话，
会出现「声图上有门、几何上是墙」这类几乎无法察觉的 bug。

### 几何构建的三个坑（实测踩过）

1. **楼层节点的 y 边界必须是半开区间**，且要留浮点容差。楼层高度是浮点累加出来的
   （`3 × 3.2 = 9.600000000000001`），闭区间会让站在四楼地板上的点先匹配到三楼节点 ——
   **丧尸低吼、石头落地这类在地板高度发出的声音会被算成从楼下发出。**
2. **楼梯间上方不能盖楼板**，梯段踏板要有厚度但不能从楼板一直填到踏面
   （否则上一层的梯段会占满这一层楼梯的头顶空间，爬到一半顶头），
   梯段上下两端要有落脚平台。
3. **每层楼梯间的梯段区必须留空**，那是从下一层上来的楼梯的洞。
   曾经为了「顶层不再往上」把顶层整个铺平，结果**出生的四楼下不去**。
   正确做法：上下两端的落脚平台每层都有，梯段区永远留空，顶层只是不再生成向上的梯段。
4. **碰撞推出要推到最近的面，不能按移动方向推。** 按移动方向推的话，
   角色一旦陷进一个大盒子（比如顶到楼板），就会被瞬间弹到盒子另一端。
