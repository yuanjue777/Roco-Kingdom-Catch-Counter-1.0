# 《校园》· M0 潜行原型（网页版）

《校园》设计文档 v1 的 **M0 里程碑**可玩验证。

> 文档 12 节原话：「**这是整个项目最关键的一步。如果 M0 不好玩，后面全部白做。
> 不要在 M0 通过前推进任何其他内容。**」
>
> 这个原型存在的唯一目的，就是在你装 Unity 之前先回答那个问题。

它**不是**游戏本体，是一台**规则验证机**：声音传播公式、丧尸反应曲线、
屏息侦查、投石引怪，全部严格按《声音系统规格 v1》实现，数值全部可以在运行时调。
你在这里调出来的那组数字，就是 Unity 里 `SO_Config_GameBalance` 的初值。

---

## 怎么跑

```bash
cd campus/web-m0

# 1. 跑规则层的单元测试（不需要浏览器）
node test/run-tests.js      # 46 条：响度表、Dijkstra 传播、修正管线、夜间曲线、性能预算
node test/sim-ai.js         # 34 条：状态机、寻路、连锁警戒、蜷伏者、追击上限

# 2. 开着玩
npx http-server -p 8080 .   # 然后打开 http://127.0.0.1:8080/index.html

# 3. 打成单文件（发布用）
node build.js               # 生成 dist/campus-m0.html
```

## 手机

同一个页面在触屏设备上会自动切到触屏操作（也可以在 URL 后加 `?touch=1` 强制打开）：

- 左下**虚拟摇杆**，推到几分走几分（模拟量，键盘是 0/1 开关量）
- 空白处**拖拽转视角**（手机没有指针锁定）
- 右侧动作键：屏息 / F 开门 / G 投石，长按进度直接画在按钮上 ——
  手机没有准星旁边的提示环，蓄力和缓慢开门的进度只能画在按钮自己身上
- 左侧修饰键：蹲 / 跑 / 贴墙（点一下切换，手机上没法"按住 Shift"）
- 体力条与状态在触屏时移到**左上角**，左下角让给摇杆、右下角让给动作键
- 声纹指示环半径跟着屏幕短边走，横屏手机只有 390px 高，写死 150px 会画到屏幕外
- 渲染分辨率在触屏设备上压到 1.25 倍 DPI ——
  这套灰盒是四层楼几百个盒子，按 3x DPR 渲染会掉到 20fps 以下，潜行手感全毁

建议横屏玩，竖屏能玩但视野窄（会有提示）。布局在 844×390 / 926×428 / 740×360 /
390×844 / 360×780 / 1024×768 六种视口下都验证过无出界、无重叠。

## 跳跃与翻越（部分文档外）

`Space` 一个键两种行为：**正前方有可翻越的边缘就翻越，没有才起跳**。

翻越判定：沿正前方每 0.2m 采样，找第一个「顶面高出脚下 0.30–1.45m、且上方有 0.95m 净空」
的位置，翻上去。0.95m 是按蹲姿通过算的，正好能钻过 1.0m 高的窗洞。

| 情形 | 结果 |
|---|---|
| 床铺（0.55m）、书桌（0.75m） | 翻上去 |
| 打开的窗（窗台 1.0m，窗洞净空 1.0m） | 翻出去 |
| 关着的窗 | 翻不了（窗扇是实体，挡人也挡声） |
| 3.2m 的墙 | 翻不了，退化为原地起跳 |
| 0.2m 的台阶 | 低于阈值，本来走上去就行，不触发 |

**哪些是文档内的、哪些是新增的：**

- 文档内：「攀爬/翻窗 −12 体力」（主文档 3.3）、「翻窗(完好窗) 响度 30」（声音规格 6.1）。
  翻越完全按这两个数走。
- **文档外**：跳跃本身。主文档 4.1 的姿态表只有走/跑/蹲/贴墙/静止，没有跳。
  新增的 `gravity 18`、`jumpSpeed 4.2`（跳起约 0.49m）、`jumpCost 6`、`jumpLand 35`
  在配置里全部标注了「文档外」，将来要砍掉或者写回文档都很容易找。

因为 `Space` 让给了跳跃，**屏息改到鼠标右键或 `Z`**。

## 已回答的文档待定问题

**主文档 13.1 问题 4「玩家能否听见丧尸的常态动静」→ 是。**
未趴伏的丧尸只要在移动就发出响度 30 的拖行脚步，趴伏的蜷伏者不发。
这个值经过反推：

| | 可听半径 |
|---|---|
| 玩家常态（阈值 25） | 2.5m —— 等于没有 |
| 玩家屏息（阈值 8） | **11m** |
| 丧尸听见你正常走路（阈值 10） | 5m |

屏息因此第一次成为真正的雷达：**你能在丧尸听见你之前两倍多的距离上先听见它**。
这也顺带缓解了前面提到的「蜷伏者呼吸只有 2m」——现在会动的丧尸都能被提前听到，
只有静止的蜷伏者仍需贴到 1m 内，那反而成了它独有的威胁。

声纹画成**环形扇区**（三角洲那种）：扇区中心是方向，**扇区宽度就是这次的方向不确定度**——
听觉熟练度越高扇区越窄，等于把「误差」直接画出来而不是藏在数值里。颜色按类别分（脚步青、撞击黄、低吼红）。

另外把主文档 10.1「非屏息时不显示声纹」改成了**常态也显示**：阈值本身已经是过滤器，
常态阈值 25 只有近处的大动静过得来，画面并不会糊；关掉它等于让玩家听见了却看不见。

声纹还会**把声源位置透视标出来**（隔墙可见的青色菱形）。
注意这等于把主文档 8.5「听觉 Lv4：声纹穿透一层 Portal 显示」白送了，
正式版应当改为按等级解锁；配置项 `hearing.revealSource` 控制开关。
方向指示仍按声音规格 5.4 用路径入口方向算，两者互不干扰。

## 投掷与贴墙的几处修正

- **预览的抛物线原本不是真的抛物线。**预览用固定 0.06 秒步长积分，实弹用逐帧变长的 dt，
  两条轨迹根本不是同一条。现在共用一个定步长积分器，实测预览落点与实弹落点误差 < 1cm。
- **侧头时眼位会跟着探出去**，投掷起点、听觉位置、被丧尸发现的判定全部按探出后的头部位置算。
  所以贴着掩体侧头扔石头是成立的动作。
- **贴墙时准星与落点对不上。**第三人称相机不在眼位上，若直接按朝向投掷，准星会横着差开一截。
  现在装配层每帧把「准星指向的远点」写给玩家，投掷朝那个点走，落点标记因此落在准星上。
- **屁股靠墙**：身体面朝墙外并向墙里贴 0.14m，头单独转向行进方向，做出贴墙侧头看走廊的姿态。

## 实现过程中发现的设计问题

这些是**文档层面的问题**，不是代码 bug。按文档 0.2.5「不要发明文档里没有的机制」，
我没有自行改数值，全部保留原值并在配置里留了开关。

### 1. 「有效半径」被算少了一半 —— 影响所有平衡标定

文档 6.1 的「室内有效半径」列（走路 10m、奔跑 22m）是**到达响度归零**的距离。
但丧尸的阈值是 10，所以**对丧尸而言的有效半径**是 `(响度 − 阈值) / k`：

| 行为 | 文档写的半径 | 对丧尸的实际半径 |
|---|---|---|
| 蹲行 10 | 5 m | **0 m**（响度低于阈值，永远听不见） |
| 走路 20 | 10 m | **5 m** |
| 奔跑 45 | 22 m | **17.5 m** |
| 石头 45 | 22 m | **17.5 m** |

差一倍。调平衡时用错列会把整个潜行难度算歪。
另外：蹲行响度 10 = 丧尸阈值 10，意味着**蹲行在数学上是绝对安全的**，
这可能不是你想要的（蹲行应该是「很难被听见」而不是「不可能被听见」）。

### 2. 蜷伏者的呼吸声几乎没有侦查价值

文档 5.2 说「屏息时能听到它们极轻微的呼吸声 —— **这是屏息作为侦查工具的核心价值**」。
按文档数值算：呼吸响度 12，屏息阈值 8，k=2 → 可听半径 `(12−8)/2 = 2m`。
再扣掉声源在地面、耳朵在 1.65m 的高度差，**水平可听距离只剩约 1.1 米**。

而蜷伏者的起身范围是 8 米。也就是说等你听见它的时候，它早就该起身了。
要让屏息真的能用来「扫房间」，`crawlerBreath` 得提到 **20–24**（可听半径 6–8m）。
调参面板里可以直接拖这个值试。

### 3. 两份文档的冲突与笔误

- 主文档 0.1 写「第七部分（技术架构）」，实际技术架构在**第十一部分**；
  0.2 的「分层见 7.1」应为 11.1。
- 声音规格 6.1 有「手枪射击 120」，但主文档 8.1 明确「没有枪」。
  按 0.3（后者优先）应删除或标注为预留。
- 声音规格 8.1 待定的「屏息能否移动」，主文档 4.2 已拍板为蹲行速度的 50%，待定项可以关掉。

### 4. 文档没定义、我留了占位值的地方

代码里都标了 `TODO`，配置里可调：

| 项 | 占位值 | 说明 |
|---|---|---|
| 调查状态的移动速度 | 游荡速度 ×1.6 | 文档只给了「游荡 1.0 / 追击 3.2」 |
| 蹲行 / 贴墙的步频 | 1.0s / 1.1s | 文档只给了走 0.7s、跑 0.35s |
| 蜷伏者呼吸间隔 | 2.5s | 文档只给了响度 12，没给频率 |
| 游荡者常态呼吸 | **0（关闭）** | 主文档 13.1 待定问题 4，改成 12 可实测 |

丧尸**不会撞门**（文档没写这个机制，虽然响度表里有「撞门 70」）。
目前关闭的门对丧尸是绝对屏障，这会让「关门」变成无代价的万能解。建议尽早定这条规则。

## 实现过程中修掉的真 bug（值得记住，Unity 版会遇到同样的）

1. **楼层节点的 y 边界必须是半开区间。** 楼层 f 的节点 y 范围是 `[f·H, (f+1)·H]`，
   相邻两层共用一个平面。用闭区间的话，一个站在 4 楼地板上的点会先匹配到 3 楼节点。
   后果极其隐蔽：**丧尸低吼、石头落地这类在地板高度发出的声音会被算成从楼下发出**，
   寻路也会把目标定到楼下去。而且 `3 × 3.2 = 9.600000000000001`，
   楼层高度是浮点累加出来的，还得加 1e-4 的容差。
2. **碰撞推出要推到最近的面，不能按移动方向推。** 按移动方向推的话，
   角色一旦因为任何原因陷进一个大盒子（比如爬楼时顶到楼板），就会被瞬间弹到盒子另一端。
3. **投掷物的落点必须取「接触点」，不能取穿透后的位置。** 原本发声位置用的是碰撞检测那一步
   的终点，而那个点已经在被撞面的另一侧了 —— 石头落在四楼地板上时，发声点在楼板下方，
   于是**在自己脚边扔一块石头会去惊动楼下的丧尸**。改成二分求出最后一个未接触的点。
   这和上面第 1 条是同一类错误：几何上差几厘米，规则上差一整层楼。
4. **楼梯间上方不能盖楼板**，梯段要留头顶空间，梯段上下两端要有落脚平台，
   并且寻路要给楼梯 Portal 挂四个顺序路点（走道→梯脚→梯顶→上层走道），
   否则丧尸会斜切过去撞在梯段侧面。

## 代码结构（严格对应主文档 11.1 的分层）

```
src/
  00-config.js      数据资产    文档里所有数字的唯一出处，业务代码不得硬编码
  01-eventbus.js    第 1 层     事件总线（含递归深度 8 的告警）
  02-modifiers.js   第 1 层     数值修正管线（Additive → Multiplicative → Override）
  03-math.js        第 1 层     引擎无关的向量/AABB/确定性随机
  04-soundgraph.js  第 1 层     声音连通图（节点 + Portal + 状态）
  05-soundsystem.js 第 2 层     Dijkstra 传播 + 听者结算
  06-hearing.js     第 2 层     听觉组件（丧尸与玩家共用）+ 反应公式
  07-time.js        第 1 层     游戏时钟 + 夜间系数曲线
  08-level.js       第 1 层     灰盒宿舍楼生成（几何与声图同源）
  09-collision.js   支撑        AABB 碰撞、地面吸附、视线、墙面探测
  10-player.js      第 3 层     玩家控制器 + 投掷物
  11-zombie.js      第 3 层     丧尸状态机 + 图上寻路 + 连锁上限
  12-render.js      表现层      three.js 灰盒渲染
  13-audio.js       表现层      程序化音效
  14-hud.js         表现层      HUD 与声纹环
  15-debug.js       工具        可视化调试 + 实时调参
  16-main.js        装配        唯一允许把各层连起来的地方
```

**00–11 完全不依赖浏览器**，`node` 里可以直接 require 跑测试。
这份分层是照着搬进 Unity 的：00–11 对应零 `UnityEngine` 引用的
`Campus.Core` 程序集，12–16 对应 Unity 侧的 MonoBehaviour 与表现层。
